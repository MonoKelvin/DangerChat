## 1. 技术决策记录（已与需求方确认）

| 编号 | 决策点 | 结论 | 理由 |
|---|---|---|---|
| ADR-01 | 后端运行时架构 | **全 Rust + ONNX Runtime**：Tauri 后端（Rust）承载全部系统能力与推理；训练阶段离线使用 Python（ultralytics）产出 ONNX 模型，发布物不含 Python 运行时 | 单进程、低资源占用、无 IPC 复杂度；与既有 Rust workspace（`spikes/m0-windows`）一致 |
| ADR-02 | 语义分析方案 | **分层：L1 规则引擎 + L2 本地语义小模型（ONNX）**，纯本地、零网络 | 隐私安全（聊天内容不出本机）；规则毫秒级兜底，模型提供语义匹配度 |
| ADR-03 | 拦截机制 | **预分析 + Enter 同步裁决**：后台预分析并缓存判定结果；钩子内仅查缓存，危险则吞键 + 弹窗；用户点「仍然发送」后仅置 allow-once 标志放行其**自己**的下一次按键，**不做 SendInput 补发** | 钩子内无重计算，满足 < 5ms 与 Windows 钩子超时约束；补发属合规红线 3 禁止行为（「只减不加」，合规文档 §3.1） |
| ADR-04 | OCR 引擎 | **RapidOCR / PaddleOCR ONNX**（det+cls+rec 三件套），`ort` crate 推理 | 中文精度业界领先；约 15MB；跨平台、可 GPU 加速、离线可用 |
| ADR-05 | GPU 加速 | ONNX Runtime **DirectML EP**，CUDA EP 编译期可选；加载失败自动回退 CPU | DirectML 覆盖 A/N/I 显卡，免 CUDA 环境 |
| ADR-06 | 前端 | **Tauri 2 + React + TypeScript + shadcn/ui + Tailwind CSS**；架构参考 `farion1231/cc-switch` | 需求指定；Tailwind 为 shadcn/ui 官方配套，纳入 |
| ADR-07 | 区域划分模型 | **YOLOv8n / YOLO11n** 训练后导出 ONNX；标签配置化 | 轻量快速、社区成熟；n 级 CPU 可跑 |
| ADR-08 | 流水线结构 | **双速流水线**：快环（输入变化 → 仅输入框 OCR + 重判，≤ 200ms）+ 慢环（窗口/像素变化 → 全链路，≤ 2s）；1.5s 心跳仅做**窗口截图 + pHash 对比**，像素未变则零推理续期 verdict；配合**草稿纪元（draft epoch）脏标记**做裁决时效判定 | 保证 Enter 时判定结果尽量新鲜，同时按键路径永不等待（§2）；心跳不重跑全链路（否则 1.5s 周期 × 2s CPU 预算 = 常驻打满一核，违反 NFR-04） |
| ADR-09 | 并发模型 | **std::thread + crossbeam channel**，后端核心不引入 tokio；推理集中在单条专用低优先级线程 | 依赖少、模型简单、钩子等 Win32 回调与 tokio 相性差；Tauri 自身 runtime 仅服务 command/event |
| ADR-10 | 语义模型精度 | **int8 量化**（bge-small-zh 级候选，常驻 ~25MB）；全量 fp32（~96MB）被守护态 ≤80MB 内存预算否决 | 短文本语义匹配精度损失可忽略（M3 实测校准阈值）；CPU 推理更快、安装包更小；全量 fp32 仅作 M3 对照基准，不进发布物 |
| ADR-11 | crate 划分 | **4 个 crate：dc-core / dc-sys / dc-pipeline / dc-bridge**（+ src-tauri 壳与 apps/*）；intercept/guard/capture/layout/ocr/sem 为 dc-pipeline 内部 module | Stage trait 已在类型层保证模块 I/O 契约，crate 边界的编译隔离收益低于 11 份清单/夹具的维护成本；模块独立性靠 trait + 模块级测试保证 |
| ADR-12 | 截图方式 | GDI **BitBlt 仅拷贝目标窗口矩形**（屏幕 DC，非窗口定向捕获） | 缓冲 ~3MB（典型 1000×700）vs 全屏双缓冲 66MB（4K×2），是守护态 ≤80MB 预算的必要手段；仍是屏幕像素，合规语义不变（C-05） |
| ADR-13 | 键盘钩子实现 | 手写 WH_KEYBOARD_LL（经 dc-sys），**不采用** rdev 等现成库 | rdev 无法可靠支持「回调内吞键 + 亚毫秒原子延迟 + IME 协同」三要素；此为有意例外，非技术债 |

## 2. 性能模型（核心约束章节）

### 2.1 感知预算与第一原则

人手对延迟的感知阈值约 **200ms**。因此确立三条第一原则，优先级高于一切功能实现：

1. **按键路径零等待**：键盘钩子回调内只做 O(1) 查询与原子标志操作，**永不**触发或等待截图、OCR、推理。发送键的附加延迟 p99 < 10ms。
2. **宁漏勿阻**：判定时效性无法确认时（无缓存 / 缓存脏 / 缓存过期）一律**放行（fail-open）**并记录日志。吞错一次键的代价远大于漏拦一次。
3. **后台分析不可感知**：全部分析在专用低优先级线程执行，单飞、限量、可被取消；即便分析耗时 2s，用户打字与发送也完全不受影响。

### 2.2 发送路径零等待设计：草稿纪元（draft epoch）

**问题**：Enter 按下瞬间，无法同步得知输入框当前内容（OCR 需百毫秒级），因此「当前判定结果是否对应输入框里的最新文本」必须有一种零成本的判断手段。

**机制**：利用键盘钩子本身——它能看到目标窗口前台时的每一次按键。

```
dc-pipeline::intercept 维护三个原子量：
  draft_epoch   : AtomicU64  —— 目标前台期间，每次「内容修改键」（可打印字符、
                                 Backspace、Delete、Ctrl+V、IME 提交）+1
  allow_once    : AtomicU64  —— 「仍然发送」放行截止时刻（毫秒）；0=无效
  verdict_slot  : VerdictSlot —— arc-swap 无锁槽位，存放最近一次 Verdict

Verdict 结构内含：
  draft_epoch   : u64         —— 本判定对应的草稿纪元
  decided_at    : Instant
  level/score/reasons/...

Enter / Ctrl+Enter 裁决逻辑（钩子内，全部为原子读，O(1)）：
  if ime_composing()           → 放行（组合中回车=选字，纪元 +1 后放行）
  if allow_once 未过期          → 消费标志并放行（用户已点「仍然发送」，30s 超时）
  v = verdict_slot.load()
  if v 存在
     && v.draft_epoch == draft_epoch.load()   // 判定之后草稿未再变过
     && v.decided_at.elapsed() < VERDICT_TTL  // 默认 2s
     && guard_state == Active
    → 按 v.level 放行或吞键+弹窗；弹窗通知入队失败时同样放行（fail-open）
  else
    → 放行 + 记 debug 日志（fail-open）
```

**性质论证**：
- 钩子内操作 = 3 次原子读 + 1 次时间比较，p99 < 1ms，满足 NFR-02。
- 若用户输入后立即按 Enter（快环还没来得及重判），`draft_epoch` 必然不等 → 放行。漏拦窗口 = 快环耗时（≤ 200ms）+ 防抖（150ms），即仅当用户在**停止输入后约 350ms 内**按 Enter 才可能漏拦。正常人打完一句话到按 Enter 的停顿 > 500ms，实际漏拦率极低；且 v1.0 接受此权衡（原则 2）。
- 若判定为 Safe 之后用户又改了内容，旧 Safe 不会误放行新内容——纪元不等即失效，语义严格。
- **鼠标操作的已知盲区（已接受权衡）**：鼠标点击切换会话、右键粘贴均不产生键盘事件、不改变 `draft_epoch`，但会使窗口像素变化。防线是 verdict TTL（2s）+ pHash 心跳（§2.3）——像素变化即触发全量慢环重判，最坏错判窗口 ≤ 2s；此窗口内按发送键按 fail-open 语义处理。
- **弹窗通道失败同样 fail-open**：吞键的前提是弹窗通知成功入队；入队失败（队列满/通道关闭）一律放行，绝不静默吞键。

### 2.3 双速流水线

| | 快环（fast loop） | 慢环（slow loop） |
|---|---|---|
| 触发 | `draft_epoch` 变化，防抖 150ms | 前台窗口/窗口 rect 变化、布局失效、**pHash 像素变化**（心跳检出） |
| 步骤 | 窗口矩形截图 → **复用缓存布局**取 `msg_input` ROI → OCR → 语义重判（chat_target 用缓存值） | 窗口矩形截图 → YOLO 全区域 → OCR（`chat_target` + `msg_input`）→ 语义判定 |
| 预算 | CPU ≤ 200ms / GPU ≤ 100ms | CPU ≤ 2s / GPU ≤ 800ms |
| 产出 | 新 Verdict（draft_epoch = 当前值） | 新 RegionLayout 缓存 + 新 Verdict |
| 降级 | 布局缓存校验失败 → 升级为慢环 | 任一 Stage 失败 → 清空 verdict_slot（fail-open） |

**心跳的廉价新鲜度检查**（关键设计，防止心跳打满 CPU）：

1.5s 心跳**不**重跑全链路（否则 1.5s 周期 × 2s CPU 预算 = 常驻打满一核，违反 NFR-04 的 ≤3%）。心跳在 pipeline-worker 上仅执行：

```
snap  = 窗口矩形截图（≤ 50ms，ADR-12）
h     = pHash(snap)                     // 感知哈希，毫秒级
if h != last_phash → 触发全量慢环        // 鼠标切换会话 / 新消息 / 任意内容变化
else              → 仅刷新 verdict_slot 的 decided_at（零推理续期）
```

心跳 CPU 开销 < 1%，同时使「鼠标操作盲区」（§2.2）的最坏错判窗口收敛到 ≤ 2s（TTL）。

**布局复用校验**（快环前置，O(1)）：
- 前台窗口句柄未变、窗口 rect 未变（截图时比对）、慢环布局缓存年龄 < 30s；
- 不满足任一条件 → 本轮快环放弃，直接排入慢环。

**调度纪律**（dc-pipeline::guard 实现）：
- **单飞**：同一时刻最多一条流水线在跑；新触发到来时若正在运行，快环请求覆盖挂起请求（merge，不排队堆积）。
- **可取消**：Stage 间传递 `CancellationToken`；draft 再次变化时取消进行中的旧快环。
- **线程**：全部流水线在 `pipeline-worker` 线程（`THREAD_PRIORITY_BELOW_NORMAL`）；ONNX Runtime intra-op 线程数限制为 `max(2, 物理核/4)`，避免打满 CPU 影响前台程序。

### 2.4 资源调度纪律（对应 NFR-04）

| 状态 | 行为 |
|---|---|
| Active（目标前台） | 钩子裁决启用；双速流水线 + pHash 心跳按 §2.3 调度 |
| Suspended（目标非前台） | 钩子直接放行一切（前台检测用事件驱动，零轮询）；流水线停止；**全部推理模型卸载**（挂起态 ≤ 25MB 预算的决定性手段）；唤醒后由首个慢环按需重载（小模型 < 500ms），重载完成前 fail-open |
| Paused（用户暂停） | 等同未安装：钩子放行一切，流水线停止，弹窗不再出现 |
| Cooldown（弹窗存续期） | 弹窗打开期间：非发送键放行（用户可继续打字，纪元正常推进），发送键一律吞但**不重复弹窗**（防连按误发）；弹窗关闭（取消/返回编辑/超时）→ Active；点「仍然发送」→ 置 allow-once 后 → Active |
| 隐私模式 | 图片日志全部不落盘；日志级别 ≥ info |

前台检测不用轮询，用 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 事件驱动，零 CPU 开销；该 API 为公开无障碍事件机制，合规。

### 2.5 关键时序图

**(a) 打字 → 快环 → Enter 拦截（正常路径）**

```
用户        钩子线程          pipeline-worker        dc-alert
 |  敲字       |                   |                   |
 |----------->| draft_epoch=41    |                   |
 |  (停 150ms) |---- trigger ----->| 快环: 截图→OCR→判  |
 |             |                   | verdict(e41,Block) |
 |  Enter      |                   |   (120ms)          |
 |----------->| e41==e41, 新鲜    |                   |
 |             | 吞键+入队成功 ----------------------->| 弹窗 |
 |  点「取消」  |                   |                   |
 |<---------------------------------------------------| 关闭 |
```

**(b) 输入后立即 Enter（fail-open 路径）**

```
 |  敲字       | draft_epoch=42    | 快环(e42) 运行中…  |
 |  Enter      | slot=e41 ≠ 42     |                   |
 |----------->| 放行 + 日志        | (完成后写 e42，但已过时) |
```

**(c) 用户确认「仍然发送」（不代发，合规红线 3 / C-08）**

```
dc-alert --command:allow--> dc-bridge --> guard.set_allow_once(30s)
   ↳ 仅置内部原子标志；严禁 SendInput 注入（CI 红线扫描零引用）
   ↳ 弹窗提示「请再按一次回车完成发送」
   ↳ 用户自己再按 Enter → 钩子消费 allow 标志 → 放行 → 消息发出
```

## 3. 总体架构与线程模型

### 3.1 分层视图

```
┌──────────────────────────────────────────────────────────┐
│ 前端 (Tauri WebView)                                      │
│  dc-ui        设置主窗口（React + shadcn/ui，按需创建）     │
│  dc-alert     拦截提示对话框（独立置顶窗口，预建常驻隐藏）    │
│  dc-uitag     打标记工具（独立进程，同技术栈）              │
├──────────────────────────────────────────────────────────┤
│ 通信层  dc-bridge   Tauri commands(拉/改) + events(推)    │
├──────────────────────────────────────────────────────────┤
│ 核心后端 (Rust, 单进程；dc-pipeline 内各 module)           │
│  guard     编排器：状态机 + 双速调度 + pHash 心跳 + 模型装卸 │
│  intercept 消息源：键盘钩子 + 前台事件 + IME 状态 + 纪元    │
│  capture   截图：窗口矩形直拷（屏幕像素，ADR-12）           │
│  layout    区域划分：YOLO ONNX 推理                        │
│  ocr       文字识别：RapidOCR ONNX 推理                    │
│  sem       文本识别：L1 规则引擎 + L2 语义模型（int8）       │
├──────────────────────────────────────────────────────────┤
│ 平台层                                                    │
│  dc-core      配置中心 / 日志中心 / 插件注册 / 模型管理    │
│  dc-sys       Windows API 封装（全仓库唯一碰 Win32 处）    │
└──────────────────────────────────────────────────────────┘
```

### 3.2 线程模型（ADR-09）

| 线程 | 职责 | 优先级 | 说明 |
|---|---|---|---|
| `main` / Tauri | WebView、commands、events | 正常 | Tauri 托管 |
| `hook-thread` | Win32 消息循环 + 低级键盘钩子回调 + 前台事件回调 | 正常（不得提升） | 回调内仅原子操作 + crossbeam `try_send`（有界队列：trigger 满则丢弃，绝不阻塞；**alert 满则改判放行**——fail-open，绝不静默吞键） |
| `pipeline-worker` | 双速流水线全部 Stage（截图/推理/OCR/语义） | BelowNormal | 单飞执行器；ONNX intra-op 线程受限 |
| `log-writer` | tracing appender 落盘 | BelowNormal | 异步非阻塞 |

**线程间通信**：全部走 crossbeam 有界 channel 传递**不可变消息**（`Trigger`、`VerdictWrite`、`AlertRequest`）；共享状态仅两处：`verdict_slot`（arc-swap）与 `guard_state`（AtomicU8）。无锁、无 wait、无回调重入——这是 §2 性能模型的结构保证。

### 3.3 模块依赖方向

```
dc-ui/dc-alert → dc-bridge → dc-pipeline（guard / intercept / capture / layout / ocr / sem）
                                          ↘ dc-core（配置/日志/注册）
dc-sys 只被 dc-pipeline 依赖（intercept 钩子、capture 截图、IME 状态）；dc-bridge 不再触碰 Win32
（「仍然发送」的放行是 dc-pipeline 内部原子标志，不经任何系统 API）。任何模块不得反向依赖上层。
```

## 4. 模块统一契约（插件机制，FR-SYS-04）

所有流水线模块实现统一 trait（契约定义于 `dc-pipeline::contract`，ADR-11），注册进 `dc-pipeline::guard` 编排器。模块间只传 DTO，不传实现；每个模块可在不知道对端实现的情况下独立实例化、喂夹具、跑测试。

```rust
/// ---- 生命周期与元信息 ----
pub trait Module: Send + Sync {
    fn id(&self) -> &'static str;
    /// 向配置中心声明本模块的配置项（键、类型、默认值、说明）
    fn config_schema(&self) -> Vec<ConfigField>;
    fn init(&mut self, ctx: &ModuleContext) -> Result<(), ModuleError>;
    fn shutdown(&mut self) -> Result<(), ModuleError>;
    /// 健康/指标：耗时直方图、失败计数，供日志与前端状态页
    fn metrics(&self) -> ModuleMetrics { ModuleMetrics::default() }
}

/// ---- 流水线阶段：纯输入 -> 输出，错误即降级 ----
pub trait Stage: Module {
    type Input: Send;
    type Output: Send;
    /// 约定：
    ///  - 不读全局状态；需要的运行期数据全部经 PipelineContext 注入
    ///  - 尊重 ctx.cancel：被 cancel 时尽快返回 Err(Cancelled)
    ///  - 不产生除 ctx.image_log 之外的副作用
    fn process(&self, input: Self::Input, ctx: &PipelineContext)
        -> Result<Self::Output, StageError>;
}

pub struct PipelineContext {
    pub run_id: RunId,                 // 本轮唯一 ID（贯穿图片日志目录名）
    pub loop_kind: LoopKind,           // Fast | Slow
    pub cancel: CancellationToken,
    pub image_log: ImageLogSink,       // debug 图片落盘句柄（隐私模式下为 Noop）
    pub device: DevicePref,            // Cpu | Gpu(DirectML) | Auto
    pub config: Arc<ConfigSnapshot>,   // 本轮开始时的配置快照（运行中不被改）
}

#[derive(thiserror::Error, Debug)]
pub enum StageError {
    #[error("recoverable: {0}")] Recoverable(String), // 本轮跳过，fail-open
    #[error("fatal: {0}")]       Fatal(String),       // 模块停用+日志+前端告警
    #[error("cancelled")]        Cancelled,
}
```

### 5.1 dc-core（配置 / 日志 / 注册 / 模型管理）

**职责**：FR-SYS-01~05。

### 5.2 dc-sys（Windows API 封装）

**职责**：全仓库**唯一**直接调用 Win32 的模块；向上提供安全、可 mock 的接口（trait `SysApi`，`RealSys` / `MockSys` 双实现）。

**接口**：
```rust
pub trait SysApi: Send + Sync {
    fn foreground(&self) -> Option<ForegroundInfo>;      // hwnd + 进程名 + pid
    fn watch_foreground(&self, cb: Box<dyn Fn(ForegroundInfo) + Send>) -> WatchGuard; // SetWinEventHook
    fn window_rect(&self, hwnd: Hwnd) -> Option<(Rect, f32 /*dpi*/)>; // 已做 DPI 物理像素换算
    fn is_window_minimized(&self, hwnd: Hwnd) -> bool;                  // IsIconic（遮挡不检测，见 FR-CAP-03）
    fn capture_region(&self, rect: Rect) -> Result<RgbaImage, SysError>; // 屏幕像素 BitBlt，仅拷贝窗口矩形（ADR-12）
    fn install_keyboard_hook(&self, cb: KeyCallback) -> Result<HookGuard, SysError>;  // WH_KEYBOARD_LL
    fn ime_composing(&self) -> bool;                     // IME 组合态（EVENT_OBJECT_IME_* 维护，公开 API，FR-SRC-09）
}
```

**实现要点**：
- 截图用 `BitBlt(GetDC(NULL))` 直接按窗口矩形拷贝，**不分配全屏缓冲**；**禁止** `PrintWindow` 与任何窗口定向捕获（合规自查项）。
- 键盘钩子安装在 `hook-thread` 的消息循环上；回调要求 < 1ms 返回，debug 构建下超时打 warn。
- **本模块不存在任何输入注入接口**：SendInput / keybd_event / mouse_event 全仓库零引用，CI 红线扫描强制（§11.3）。「仍然发送」的放行由 dc-pipeline 内部 allow-once 原子标志实现，不经过 Win32。

**错误矩阵**：窗口消失/最小化 → `SysError::WindowUnavailable`（上层转 Recoverable）；钩子安装失败 → Fatal（核心功能不可用，前端告警）。

**测试矩阵**：

| ID | 用例 |
|---|---|
| UT-SYS-01 | MockSys 注入窗口序列，坐标/DPI 换算正确（1.0/1.25/1.5） |
| UT-SYS-02 | IME 组合态 mock：composing=true 时钩子层放行发送键且纪元 +1（联动 UT-INT-07） |
| IT-SYS-01（手动，`--ignored`） | 真实桌面：前台检测、窗口矩形截图非空且尺寸正确、IME 事件在记事本 + 微软拼音下正确翻转 |

### 5.3 dc-pipeline::intercept（消息源模块）

**职责**：FR-SRC-01~08；§2.2 草稿纪元机制的唯一实现者。

**内部结构**：
```
KeyHookAdapter   —— 挂 dc-sys 键盘钩子；回调内：前台匹配 → IME 判定 → 分类按键 → 原子操作/裁决
ForegroundTracker—— 挂 dc-sys.watch_foreground；维护 target_active: AtomicBool + 3s 冷却
DraftTracker     —— draft_epoch: AtomicU64；识别内容修改键（可打印/Backspace/Delete/Ctrl+V/IME 提交）
                    另维护 allow_once: AtomicU64（「仍然发送」放行截止毫秒时刻，0=无效）
GuardStateMachine—— Active / Suspended / Paused / Cooldown（弹窗存续期）四态（§2.4）
TriggerBus       —— 向 pipeline-worker 发 FastTrigger / SlowTrigger（有界 try_send）
```

**钩子回调伪码**（全部原子操作，目标 < 1ms）：
```rust
fn on_key(k: KeyEvent) -> HookAction {
    if state() == Suspended || state() == Paused { return Pass; }
    if sys.ime_composing() {                       // 输入法组合中：绝不吞键（FR-SRC-09）
        if k.is_send_key(config.send_key) { epoch().fetch_add(1); } // 回车=选字确认→纪元+1
        return Pass;
    }
    if state() == Cooldown {                       // 弹窗存续期：发送键吞、不重复弹窗
        return if k.is_send_key(config.send_key) { Swallow } else { Pass };
    }
    if k.is_send_key(config.send_key) {            // Enter 或 Ctrl+Enter
        if take_allow_once(now) { return Pass; }   // 用户已点「仍然发送」（30s 超时）
        match verdict_slot.load() {
            Some(v) if v.draft_epoch == epoch() && v.fresh(TTL) => match v.level {
                Safe => Pass,
                Warn | Block => {
                    if alert_bus.try_send(v).is_ok() { enter_cooldown(); Swallow }
                    else { Pass }                  // 弹窗通道异常 → fail-open，绝不静默吞键
                }
            },
            _ => { log::debug!("fail-open: no fresh verdict"); Pass }
        }
    } else {
        if k.modifies_content() { epoch().fetch_add(1); trigger_bus.offer_fast(); }
        Pass
    }
}
```

**配置项**：`guard.send_key`("enter"|"ctrl+enter") / `guard.enabled` / `target.process_name`(默认 "WeChat.exe") / `guard.verdict_ttl_ms`(默认 2000) / `guard.fast_debounce_ms`(默认 150) / `guard.allow_once_timeout_ms`(默认 30000)。

**错误矩阵**：

| 场景 | 行为 |
|---|---|
| trigger 队列满 | 丢弃（下个按键还会再触发），debug 计数 |
| alert 队列满 / 通道关闭 | 回调改判放行（fail-open），绝不静默吞键；error 日志 + metrics 计数 |
| 钩子回调超时（debug 检测 > 5ms） | warn 日志 + metrics 计数；连续超阈值自动 fail-open 一段时间 |
| 目标进程名配置为空 | 模块 init 拒绝，前端提示 |

**测试矩阵**：

| ID | 用例 |
|---|---|

| UT-INT-02 | 内容键 → draft_epoch 递增且触发 fast offer；非内容键（方向键/F 键）不递增 |

### 5.4 dc-pipeline::capture（截图模块）

**职责**：FR-CAP-01~05。`Stage<Input=CaptureRequest, Output=WindowSnapshot>`。

**算法**：
```
1. hwnd = ctx 目标窗口；若 is_window_minimized 或目标非前台 → Recoverable
2. (rect, dpi) = window_rect(hwnd)
3. img = capture_region(rect * dpi)       // 屏幕像素直拷窗口矩形（ADR-12，物理像素系）
```

**优化**：位图缓冲按**窗口矩形尺寸**一次性分配并复用（典型 ~1000×700 RGBA ≈ 3MB，替代全屏双缓冲 66MB——守护态 ≤ 80MB 预算的必要手段）；前台窗口不存在整体遮挡，置顶窗口局部遮挡属可接受边角（OCR 异常 → Recoverable → fail-open）。1080p 实测目标 ≤ 50ms（典型 10~25ms）。

**错误矩阵**：窗口不可用 → Recoverable（本轮跳过）；BitBlt 失败 → Recoverable + 计数，连续 5 次升 Fatal。

**测试矩阵**：

### 5.7 dc-pipeline::sem（文本识别/语义判定模块）

**职责**：FR-SEM-01~07。`Stage<Input=OcrResult, Output=Verdict>`。

**内部结构**：
```
RuleEngine   —— L1：违禁词库（rules.toml）× 场景画像（contacts.toml），Aho-Corasick 多模匹配 + 正则补充
Embedder     —— L2：ONNX 句向量模型（**int8 量化**，常驻 ~25MB，ADR-10）；启动时预计算场景模板向量并缓存
ScenarioStore—— 画像与场景模板：formal/casual 各一段可配置描述文本
Fusion       —— 级别融合与理由生成
```

**判定算法**：
```rust
fn judge(input: OcrResult, ctx) -> Verdict {
    let profile = contacts.profile_of(&input.chat_target).unwrap_or(Formal); // 未标记=正式(保守)
    // L1（永远启用，毫秒级）
    if let Some(hit) = rules.first_hit(&input.draft_text, profile) {
        return Verdict::from_rule(hit, profile);          // severity→Warn/Block，短路
    }
    // L2（可开关；空草稿直接 Safe）
    if l2_enabled && !draft_text.is_blank() {
        let sim = cosine(embed(draft_text), scenario_vec(profile));
        return Verdict::from_score(1.0 - sim, threshold(profile)); // 低于阈值→Warn/Block
    }
    Verdict::safe()
}
```

**阈值与级别**：`sem.threshold.formal`(默认 0.55) / `sem.threshold.casual`(默认 0.35)；score 越过阈值 +0.15 区间升 Block，区间内 Warn。命中理由示例：`命中违禁词「sb」(severity=block)` / `与正式场景语义不匹配，相似度 0.31 < 0.55`。

**fail-open**：Embedder 加载失败 → `l2_enabled` 视为 false，仅 L1 + warn 日志（NFR-07）。

**配置项**：`sem.l2_enabled` / `sem.threshold.*` / `sem.rules_path` / `sem.contacts_path` / `sem.scenario_templates`（formal/casual 描述文本）。

**测试矩阵**：

| ID | 用例 |
|---|---|
| UT-SEM-01 | 规则矩阵：词条 × formal/casual × 预期级别（数据驱动 50+ 行） |
| UT-SEM-02 | 未标记对象按 formal 保守处理 |
| UT-SEM-03 | L1 命中短路，L2 不被调用（mock 计数断言） |

### 5.8 dc-pipeline::guard（编排器）

**职责**：状态机 + 双速调度 + pHash 心跳 + Verdict 槽位 + 模型装卸载生命周期；Stage 装配（从 PluginRegistry）。

**调度器核心**：
```rust
enum Trigger { Fast, Slow, Heartbeat }
// pipeline-worker 主循环
loop {
    let trig = merge(rx.recv());            // 有界队列；连续 Fast 合并为一次；Fast 优先于挂起的 Slow
    match trig {
        Heartbeat => {                       // 1.5s 固定周期（仅 Active 态）
            let snap = capture.run(..)?;                     // 窗口矩形截图（≤50ms）
            if phash(snap) != last_phash { run(Slow)?; }     // 像素变化才全链路
            else { verdict_slot.refresh(now); }              // 零推理续期 decided_at
        }
        Fast => {
            if !layout_cache.reusable(&current_window)? { run(Slow)?; continue; }
            let snap = capture.run(..)?;                     // Stage: capture
            let ocr  = ocr.run((&snap, &layout_cache.input_only()), ..)?;
            let v    = sem.run(ocr.with_cached_target(&target_cache), ..)?;
            verdict_slot.store(v.with_epoch(draft_epoch.load()));
        }
        Slow => {
            let snap = capture.run(..)?;
            let layout = layout.run(snap.clone(), ..)?;
            let ocr  = ocr.run((&snap, &layout), ..)?;
            let v    = sem.run(ocr, ..)?;
            layout_cache.store(layout); target_cache.store(ocr.chat_target);
            verdict_slot.store(v.with_epoch(draft_epoch.load()));
        }
    }
}
// 任一 Stage Recoverable → verdict_slot.clear()（fail-open）；Fatal → 停用+告警
```

**模型生命周期**（NFR-04 内存分级的执行者）：Suspended → 卸载全部 ONNX session（挂起态 ≤ 25MB）；Active → 经 ModelStore 异步重载（小模型 < 500ms），重载完成前 Slow/Fast 触发直接跳过（fail-open）。

**布局复用校验**（`layout_cache.reusable`）：窗口 hwnd 未变 && rect 未变 && 年龄 < 30s。

**测试矩阵**：

| ID | 用例 |
|---|---|
| UT-GRD-01 | 全 mock Stage 的 Fast/Slow 端到端：verdict_slot 内容与纪元正确 |
| UT-GRD-02 | 单飞：运行中再来触发被合并而非排队 |
| UT-GRD-03 | Stage Recoverable → slot 清空（下次按键必放行） |
| UT-GRD-04 | 布局复用三条件各自的失效分支 → 升级 Slow |
| UT-GRD-05 | 配置热更新：下一轮使用新快照，本轮不受影响 |
| UT-GRD-06 | 心跳：pHash 未变 → 仅续期 decided_at（零 Stage 调用）；pHash 变化 → 触发 Slow |
| UT-GRD-07 | 模型生命周期：Suspended 卸载后触发被跳过（fail-open），重载完成后恢复 |

## 9. 性能预算汇总（对应 NFR-01~05）

| 路径 | 环节 | 预算（GPU / CPU） | 线程 |
|---|---|---|---|
| 按键路径 | 钩子回调（含裁决） | < 1ms / < 1ms（p99；NFR 上限 5ms） | hook-thread |
| 按键路径 | 吞键 → 弹窗可见 | ≤ 300ms | event → dc-alert |
| 快环 | 窗口矩形截图 | ≤ 50ms | pipeline-worker |
| 快环 | OCR（msg_input 单 ROI） | ≤ 60ms / ≤ 150ms | pipeline-worker |
| 快环 | L1+L2 重判（int8） | ≤ 50ms / ≤ 200ms | pipeline-worker |
| 快环 | **合计** | **≤ 100ms / ≤ 200ms** | — |
| 心跳（1.5s） | 窗口矩形截图 + pHash | ≤ 60ms；未变化时零推理 | pipeline-worker |
| 慢环 | 截图+YOLO+双 ROI OCR+判定 | ≤ 800ms / ≤ 2s | pipeline-worker |
| 常驻 | 后端进程内存：**挂起 ≤ 25MB / 守护 ≤ 80MB**（int8 模型常载 + 窗口矩形缓冲） | — | 全进程 |
| 常驻 | 守护态空闲 CPU | ≤ 3% | — |

**内存口径说明**：上表后端进程预算按 NFR-04「私有工作集、单独核算」；WebView2 进程内存不计入（常态仅 dc-alert 一个预建实例，设置主窗口关闭即销毁）。挂起态 25MB 由「模型全卸载 + 无分析缓冲」保证；守护态 80MB ≈ 进程基线 15 + ort 运行时 ~30 + YOLO 6 + OCR 15 + int8 语义 25 − 复用缓冲。

**冗余说明**：Enter 时 verdict 不可用 → 放行（§2.2），因此上表中任何一环节超时都**不会**转化为用户可感知延迟，只影响拦截及时性；快环合计 ≤ 200ms 是为压缩漏拦窗口，而非按键延迟。
