## 1. 先说结论

### 1.1 必须接受的事实

**微信的协议文本，把"读取微信界面"和"制作、发布、传播此类工具"都明确列为禁止行为，没有为"只读"或"无障碍工具"留豁免口子。**

这意味着：**危信的核心功能，在协议文本层面就落在禁止范围内。** 我们没有办法通过技术选型让它"完全合规"——只能让它**尽可能远离腾讯实际会处罚的那些行为**，并且**把真实情况坦白告诉用户**。

不粉饰这一点，是这个产品能被信任的前提。

### 1.2 两个维度必须分开看

| 维度 | 问题 | 危信的答案 |
| :-- | :-- | :-- |
| **A. 是否违反协议文本** | 白纸黑字写没写 | **可能违反**。核心功能（读取界面）被 1.2.6 字面覆盖 |
| **B. 实际被封号的风险** | 腾讯真正检测什么 | **低**。我们不产生任何一个已知靶点的特征 |

腾讯实际的检测靶点是三样：**异常加载模块**（注入的 DLL）、**行为特征**（自动群发、高频操作、定时任务）、**用户举报**。危信一样都不沾。

调研中**未找到任何"仅本地处理、不自动发送"类工具被封号的官方案例或公告**。微信安全中心能检索到的最相关公告是 2015 年那条针对"修改主题类非法软件"的提醒，针对的是修改类，不是只读类。

**但"没查到案例"不等于安全。** 腾讯保留随时认定违规的权利，这一点必须告诉用户。

### 1.3 由此确定的四条产品红线

| # | 红线 | 状态 |
| :-- | :-- | :-- |
| 1 | **不接触微信进程**：不注入 DLL、不读写其内存、不 hook 其函数 | 已排除，代码库中不保留任何相关路径 |
| 2 | **不接触微信数据**：不读取、不解密、不导出聊天数据库或任何微信文件 | 已排除 |
| 3 | **不向微信发送任何东西，也不拦截微信的任何事件**：不注入按键、不注入点击、不自动发送、不群发、不自动回复；不拦截鼠标点击（含发送按钮）、不拦截微信应用的任何窗口消息——**只拦截系统键盘的回车** | 已排除，平台层不存在输入注入接口 |
| 4 | **不上传任何内容**：默认零网络；云端为用户主动开启且只发用户自己写的草稿 | 默认关闭 |

**危信对微信只做一件事：看屏幕。以及阻止用户自己的按键到达微信。**

### 2.3 《微信隐私保护指引》—— 对我们有利的关键条款

出处：<https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=privacy>（更新/生效日 2026-08-17）

> **1.35 我们不会收集你的聊天记录。你在微信中的聊天记录会存储在你的终端设备**，你可以选择自行备份、删除或在不同设备中转移。
>
> **1.43** 当你在微信中复制和粘贴信息时，我们将申请使用你的剪切板，**我们仅在本地识别剪切板内容，不会上传你剪切板的信息至我们的服务器**。

**这两条的意义**：聊天内容与草稿是**用户本地自有数据**，腾讯自己都不收集。所以用户在自己机器上处理自己的草稿，不受微信隐私协议约束。1.43 还提供了一个有力的类比——**微信自己也承认"仅在本地识别、不上传"是可接受的处理方式**，这正是危信对待草稿的方式。

### 2.4 《个人信息保护法》—— 关键豁免

出处：<http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html>

> **第七十二条　自然人因个人或者家庭事务处理个人信息的，不适用本法。**

用户在自己的设备上，为自己的目的，分析自己参与的会话——这属于"个人事务处理个人信息"，很可能落入本条豁免。

> 第四条　……个人信息的**处理**包括个人信息的收集、存储、使用、加工、传输、提供、公开、删除等。

这条提醒我们：一旦把内容**传输**给第三方（云端 LLM），豁免的边界就变模糊了。所以 L3 的设计必须严格限定外发范围（见 4.4）。

## 3. 行为逐条评估

| # | 行为 | 协议文本 | 实际风险 | 法律风险 | 危信是否做 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| B1 | UIA 只读控件文本 | 可能违反（1.2.6"读取……界面"） | 低 | 无 | **❌ 已放弃** |
| B2 | 截屏 + 本机 OCR | 可能违反（灰区，最弱形态） | **最低** | 无 | **✅ 唯一采集路线** |
| B3-a | 键盘钩子**阻断**回车 | 灰区 | 低 | 无 | **✅ 做** |
| B3-b | `SendInput` **向微信补发**回车 | 可能违反（近 1.2.9"滥用系统权限操作微信"） | 中 | 无 | **❌ 已放弃** |
| B4 | 向微信进程写内存 | **明确违反**（1.2.4、1.2.5） | 高 | **可能触及刑法 285/286** | **❌ 永久排除** |
| B5 | DLL 注入 + hook | **明确违反**（1.2.2/1.2.4/1.2.5/1.2.7） | 最高 | **可能触及刑法 285/286** | **❌ 永久排除** |
| B6 | 读取/解密聊天数据库 | **明确违反**（1.2.7 + 规范 4.1） | 高 | **可能触及刑法 285 条第 2 款** | **❌ 永久排除** |
| B7 | 自动发送/群发/自动回复 | **明确违反**（1.2.6/1.2.9/3.4） | **高（头号靶点）** | — | **❌ 永久排除** |
| B8 | 草稿发第三方 LLM | 灰区（自有草稿低；含他人消息则可能违反 4.1） | 低—中 | PIPL 边界变模糊 | **⚠️ 默认关闭，严格限定范围** |
| B9 | 开源发布 | 可能违反（1.2.6 末句"制作、发布、传播"） | 取决于载荷 | 纯 OCR 工具不属"专门用于侵入/控制"，不成立提供工具罪 | **✅ 做，坦白告知** |

### 3.1 关于 B3 的取舍

补发回车（吞掉回车 → 分析 → 安全则 `SendInput` 重新注入）本可以是体验最顺滑的实现。但它的实质是**用系统级输入能力去驱动微信执行发送动作**，与 1.2.9 的"滥用系统权限能力操作微信软件"字面接近，而且很难向用户解释"我们不操作微信"。

**决策：只做减法，不做加法。**

- 危信可以**阻止**用户自己的按键到达微信（这是所有热键管理器都在做的事，对象是用户自己的键盘）
- 危信**绝不向微信发送**任何按键、点击或消息

**这条界线的好处是它可以被验证**：用 API Monitor 或 Process Monitor 观察，危信进程从不调用 `SendInput` / `PostMessage` / `SendMessage` 向微信窗口投递任何东西。这是可以写进 README 并被第三方复核的硬承诺。

**代价**：用户点"我已知晓"后，需要自己再按一次回车；缓存未命中且判定安全时，也需要再按一次。具体的体验处理见《03》第 5 章与《05》5.5。

### 3.2 关于 B9 的取舍

1.2.6 末句"或制作、发布、传播上述工具、方法等"字面覆盖了开源发布这件事本身。

**决策：照常开源，但坦白告知。**

理由：

1. **纯 OCR 工具不需要逆向微信即可实现**，所以不触发 1.2.2（反向工程条款）。
2. **不属于"专门用于侵入、非法控制计算机信息系统的程序、工具"**，刑法 285 条第 3 款"提供工具罪"一般不成立。这条判断的前提是产品中**不含**任何注入、破解、自动群发能力——所以红线 1/2/3 不只是道德选择，也是法律风险的分界线。
3. 隐瞒风险比坦白风险更糟。一个能看到用户全部聊天草稿的工具，如果连"用它可能违反微信条款"都不说，用户凭什么信任它在别的事情上说真话。

## 4. 设计红线的具体落实

### 4.1 采集：只看屏幕

| 能力 | 用什么 | 为什么不用别的 |
| :-- | :-- | :-- |
| 找到微信窗口 | `FindWindow` + `DwmGetWindowAttribute` | 操作系统窗口管理接口，与任何任务栏/窗口管理器做的事相同 |
| 判断微信是否前台 | `GetForegroundWindow` + `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` | 同上，不读微信任何内容 |
| 截取屏幕画面 | DXGI Desktop Duplication / WGC 显示器捕获 / GDI（三级降级） | 显示器级系统截屏接口，与远程桌面/录屏软件相同；**不使用任何窗口定向捕获**（窗口定向方式会向目标窗口发消息或画捕获边框） |
| 划分界面区域 | **图像结构分割**（灰度 + 行列投影） | 不用 UIA——UIA 读的是微信的控件树，字面上更直接地落入 1.2.6 |
| 识别文字 | 本机 ONNX OCR | 作用于图片像素，不作用于微信的数据结构 |
| 判断焦点是否在输入框 | **图像判定**（输入框区域像素在按键后变化） | 不用 UIA |
| 输入法组合状态 | `SetWinEventHook(EVENT_OBJECT_IME_*)` | 这是关于**输入法窗口**的系统事件，与微信无关 |

**所有这些接口，读的都是操作系统提供的信息或屏幕像素，没有一个是微信的接口。**

### 4.2 拦截：只减不加

```
允许：SetWindowsHookEx(WH_KEYBOARD_LL) 回调中 return 1   ← 阻止按键传递
禁止：SendInput / PostMessage / SendMessage 向微信投递任何内容
```

代码层面强制：
- `platform/api/` 中**不存在** `IInputInjector` 接口
- CI 增加一条静态检查：源码中出现 `SendInput` / `keybd_event` / `mouse_event` / 向外部窗口 `PostMessage` 一律报错（Watchdog 探针除外，见下）

> **唯一例外**：看门狗用 `SendInput` 注入一个无害按键探测钩子是否存活（《03》5.5）。该探针**注入到自己的进程**，不指向微信，且带自标记立即被自己的钩子消费掉。这一处在代码中集中实现并加显著注释，CI 白名单单独放行。

### 4.3 上下文采集：更严的约束

上下文采集读的是**别人**的消息（《03》4.6），虽然只读屏幕上已可见的部分，仍需对应《使用规范》4.1。4.1 的完整表述是"未经其他微信用户明确同意……复制、存储、使用或传输其他微信用户数据，**侵害其他微信用户合法权益的**"——构成违规需要"侵害合法权益"这个要件。

我们的设计确保不满足该要件：

| 约束 | 实现 |
| :-- | :-- |
| 不复制 | 原始文本只在内存中存活一次分析的时间 |
| 不存储 | 不落盘、不写日志、不进数据库（`intercept_log` 表**没有**对应字段，是有意的） |
| 不传输 | L3 云端**永不**发送他人消息，只发数值化的语域分数 |
| 用完即毁 | RAII 包装 + `SecureZeroMemory` |
| 范围最小 | 只读屏幕上已渲染、用户本人已经看得到的那几条 |
| 不操作界面 | 绝不滚动、不点击、不改窗口——用户的滚动位置在采集前后完全不变 |
| 可关闭 | 设置项，用户可随时关掉 |

### 4.4 云端：只发用户自己写的字

启用 L3 时，请求体**只允许**包含三样：

```jsonc
{
  "draft": "用户自己在输入框里写的那句话",
  "conversation": "会话显示名称",
  "register_score": 0.82          // 数值，不是文本
}
```

**绝不包含**：他人消息原文、历史记录、联系人列表、微信号、任何标识用户身份的信息。

《08》的验收项 P-07 要求**抓包解 TLS 逐字段核对**这一点，每个版本都跑。

## 5. 告知用户

### 5.1 首次启动告知页

用户第一次运行时必须看到，勾选后才能使用。不能藏进设置，不能用小字。

内容包含三块：

**① 它做什么、不做什么**

> 危信通过**截取你的屏幕画面并在本机识别文字**来工作。
>
> 它**不会**：
> · 注入或修改微信程序
> · 读取或解密微信的聊天记录文件
> · 替你发送任何消息
> · 把你的聊天内容上传到任何服务器（除非你主动开启云端增强）
>
> 它**只会**：阻止你自己的按键到达微信，然后提醒你。

**② 协议风险，原文照贴**

> **请注意**：微信《软件许可及服务协议》8.2.1.6 与《微信个人账号使用规范》1.2.6 规定，禁止"通过非腾讯开发、授权的第三方软件……对微信软件及其组件、模块、界面、数据等进行访问、读取或控制"。
>
> **使用本类工具可能违反微信条款，存在账号被限制或封禁的风险，责任由使用者自行承担。**
>
> 我们已尽力把风险降到最低：不接触微信进程、不接触微信文件、不自动发送任何消息——这些正是微信实际处罚的行为。但我们无法保证腾讯不会做出不同认定。

### 5.2 README 结构

README 必须**先回答风险，再讲功能**。顺序本身就是态度：

1. 这是什么（一句话）
2. **它读什么、传什么、会不会让我被封号** —— 前置，不藏
3. 协议风险告知（贴原文 + 链接）
4. 它明确不做的事（四条红线）
5. 如何自行验证
6. 功能介绍
7. 安装使用
8. 免责声明

## 6. 这些红线怎么保证不被慢慢磨掉

设计文档写得再好，也挡不住三个月后某次"就加一个小功能"。所以红线需要机制保障：

| 机制 | 内容 |
| :-- | :-- |
| **CI 静态检查** | 禁止出现 `SendInput`（白名单除外）、`WriteProcessMemory`、`CreateRemoteThread`、`ReadProcessMemory`、任何指向微信目录的路径常量 |
| **依赖审查** | 禁止引入任何微信逆向相关的库 |
| **验收项** | 《08》P-10（Process Monitor 全程监控）、P-11（界面未被操作）、P-07（云端发送内容）每版本必跑 |
| **PR 模板** | 增加一栏"本 PR 是否触碰《09_合规与风险》第 1.3 节的四条红线？"，必须显式回答 |
| **Issue 处理原则** | 对"能不能加个自动回复""能不能读历史记录"这类需求，统一以本文档为依据拒绝，并链接到此处。**这类需求会持续出现，需要一个可以直接引用的、不必每次重新论证的答案。** |
