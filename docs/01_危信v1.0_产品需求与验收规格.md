# 危信 v1.0 产品需求与验收规格

## 1. 文档目的

本文将两份初始设想收敛为可实施、可测试、可上线的 v1.0 产品边界。需求冲突时，优先级为：合规红线 > 发送安全 > 隐私 > 正确性 > 性能 > 体验 > 扩展性。

## 2. 产品定义

危信是一款 Windows 桌面端“消息发送前风险确认助手”。用户在受支持聊天软件中按下发送快捷键时，危信短暂阻止该键，基于当前屏幕上可见的聊天对象、上下文和输入框草稿进行本地识别；发现错发、场景不匹配或敏感表达风险时提醒用户，由用户决定修改或再次手动发送。

危信不是内容审查系统、企业 DLP、微信插件、聊天记录读取器或自动发送工具，也不承诺消除所有误发。

### 2.1 核心价值

- 在消息仍未发送时，降低“把私人表达发到工作群/客户群”等高后果误发概率。
- 通过纯屏幕观察与本地优先处理，尽量降低账号、隐私和系统资源风险。
- 在任何不确定状态下保持消息留在输入框，不自动代替用户发送。

### 2.2 产品红线

本节摘要不替代《合规与风险说明》；实现必须同时遵守原文。

1. 不注入、Hook、扫描或读写目标程序进程、内存、模块和函数。
2. 不读取、解密或导出目标程序文件、数据库、网络流量和内部协议。
3. 不调用 `SendInput`、`PostMessage`、`SendMessage` 等向目标程序投递输入；危信只阻止系统键盘的发送键，最终发送必须由用户再次物理按键完成。
4. 默认零网络；云端增强必须由用户单独开启，并只允许发送白名单字段。
5. 不持续录屏；仅为一次有效发送事务获取一帧或极短帧序列，原图默认不落盘。
6. 不做自动回复、群发、撤回、鼠标点击或任何改变目标程序状态的自动化。

## 3. 用户与场景

### 3.1 目标用户

- 同时使用私人聊天、工作群和客户群的 Windows 用户。
- 经常在多个会话间切换，且误发后果较高的职场用户。
- 不接受读取聊天数据库、注入插件或默认上传内容的隐私敏感用户。

### 3.2 核心场景

1. 从朋友私聊切换到工作群后，误把吐槽、抱怨发送出去。
2. 在名称相近的联系人或群聊之间选错目标。
3. 给正式对象发送攻击性、过度随意、含隐私或凭据的文本。
4. 用户将某些会话标记为工作、客户、私人等，使判断结合场景。
5. 风险提醒后，用户返回修改；或明确知晓后返回目标窗口，再按一次发送键。

## 4. v1.0 范围

### 4.1 P0 必须交付

- Windows 10 22H2、Windows 11，x64，普通用户权限运行。
- 发布支持矩阵内的 Windows 微信桌面版；适配基于屏幕像素，不使用微信接口。
- 支持 `Enter`、`Numpad Enter`、`Ctrl+Enter` 的精确组合配置。
- 识别当前会话显示名称、输入框可见纯文本和最近可见上下文。
- 布局可信度、OCR 可信度与文本完整性检查。
- 本地规则分析；本地轻量语义模型满足质量门槛后才启用。
- 可选云端 LLM 增强，默认关闭、供应商可替换、严格结构化输出。
- `放行许可 / 风险确认 / 无法完成检测` 三类结果；三类结果均不由软件代发。
- 系统托盘、主设置窗口、非抢焦点状态提示、独立风险确认窗口。
- 保护范围、会话标签、排除项、检测强度、隐私、日志与诊断设置。
- 默认仅元数据日志；主产品 P0 不提供真实草稿、他人消息或调试截图持久化。
- 首次启动告知、支持状态自检、签名安装包、卸载与更新检查。

### 4.2 P1（v1.x）

- 鼠标发送前保护的合规可行性研究，不承诺交付。
- 更多聊天软件适配器与布局配置。
- 用户自定义风险短语、正则与场景标签。
- 可下载的本地模型包、脱敏诊断包、布局校准向导增强。

### 4.3 v1.0 明确不做

- macOS、Linux、UWP 和移动端。
- 图片、表情、语音、视频、文件内容或文件名语义分析。
- 全量聊天历史、滚动读取、联系人唯一身份识别。
- UI Automation 控件树读取、OCR 之外的目标应用数据访问。
- 公共插件市场或加载第三方可执行代码。
- 企业审计、管理员远程策略、强制永久阻断。
- 自动采集或上传训练数据。
- 将 `dc_uitag` 打包进普通用户主产品；它是独立开发工具。

## 5. 关键产品决策

### 5.1 安全消息也需再次按键

第一次发送键被阻止后：

- 低风险：提示“已检查，再按一次发送”；生成短时一次性许可。
- 有风险：用户选择“仍要发送”只记录本事务的覆盖批准；回到原窗口完成新鲜快照复核后才生成一次性许可，再提示用户按发送键。
- 检测失败：提示“本次未完成检测”；用户可取消、重新检测，或明确选择“本次跳过检测”后取得一次性许可。

软件永远不合成按键。该取舍牺牲一次操作，换取可验证的“危信不向微信发送任何输入”边界。

### 5.2 布局定位不以 YOLO 为前提

v1 优先使用版本化布局配置、归一化坐标、结构锚点和用户校准。10–20 张截图只足以校准单一布局，不足以训练覆盖主题、DPI、窗口尺寸和版本变化的发布级通用检测器。YOLO 只作为后续可替换定位器，在真实多样化数据达到门槛后引入。

### 5.3 本地优先，云端只做不确定样本

每次发送必经路径为捕获、布局检查、OCR、本地规则；本地模型是可选增强。云端只在用户开启、剩余截止时间充足且本地结果不确定时调用，不能成为每次发送的强依赖。

## 6. 核心用户旅程

### 6.1 首次启用

1. 展示产品能力、账号协议风险、隐私数据流与明确不做事项。
2. 用户勾选已阅读后进入配置，不得预勾选云端、开机启动或内容日志。
3. 用户选择目标窗口、实际发送快捷键、保护强度和是否使用上下文。
4. 执行前台识别、截图、布局、OCR、输入法与键盘阻止测试。
5. 所有必需项通过后状态变为“保护中”；失败时给出具体修复步骤。

### 6.2 正常发送

1. 发送键到达系统 Hook。
2. 非目标前台或未启用：立即透传。
3. 有效目标：阻止该次 keydown、重复事件和配对 keyup，创建唯一发送事务。
4. 100 ms 内显示不抢焦点的“正在检查”。
5. 截取目标所在屏幕，按窗口边界在内存中裁剪；识别布局、对象、草稿和必要上下文。
6. 执行本地分析及可选增强。
7. 结果返回后重新校验前台窗口、会话与草稿指纹。
8. 低风险则显示一次性许可提示；风险或失败则显示确认窗口。
9. 用户返回原会话再次按键；许可仍有效才透传该物理按键，否则重新检查。

### 6.3 风险确认

- 显示“消息尚未发送”、会话名称、最多三条简短理由。
- 默认焦点和主操作为“返回修改”；`Esc` 等价于返回修改。
- `Enter` 不得直接触发“仍要发送”。
- “仍要发送”只记录本事务的 `override_approved`，随后关闭弹窗；用户回到原目标窗口后，后台以新鲜屏幕快照重新校验会话和草稿，校验通过才生成一次性许可。软件不恢复焦点、不合成输入。
- 从危信风险窗切回该事务绑定的原目标窗口，是 `override_approved` 进入复核的预期迁移，不单独使批准失效；切到任何其他窗口、会话、草稿变化、配置变化或继续编辑都会撤销批准/许可。

## 7. 功能需求

### FR-01 运行状态

状态至少包括：`未配置、保护中、已暂停、分析中、目标不受支持、分析服务不可用、需要重新校准`。托盘和设置首页必须回答“当前是否受保护”及原因。

### FR-02 目标资格判定

仅当以下条件全部成立才阻止发送键：目标为前台、版本/布局受支持、用户已启用、快捷键精确匹配、输入法不处于组合确认状态、系统会话未锁定、当前无冲突事务。任何一项不确定时不得全局误吞非目标应用按键。

### FR-03 发送事务

事务包含 `transaction_id、目标窗口快照、上下文代次、会话指纹、草稿指纹、用户活动代次、按键类型、单调时钟截止时间`。全局只允许一个活动事务。`HELD/CAPTURING/ANALYZING/REVALIDATING/AWAITING_REVIEW/UNAVAILABLE` 等非空闲状态中，任何已配置发送键的 keydown、自动 repeat 和配对 keyup 都一律阻止，不排队、不创建第二事务，并按物理键身份维护配对；普通编辑事件只递增用户活动代次并使旧结果失效。

### FR-04 截图与布局

- 仅在有效事务中捕获；目标不在前台时不截图。
- 生产模式使用显示器捕获并在内存中裁剪目标窗口，遵循合规文档的捕获边界。
- 输出布局配置版本、区域、置信度和失败码。
- DPI、主题、窗口尺寸或基于屏幕几何锚点计算的 `layout_signature` 超出支持矩阵时，进入“需要重新校准”；为遵守红线，v1 不读取目标程序 EXE 版本资源。
- 黑帧、遮挡、最小化、跨屏裁剪不可信时不得产出低风险许可。

### FR-05 OCR 与文本完整性

输出会话名称、草稿、最近 3–8 条可见上下文、字段/行置信度、引擎和模型版本。若草稿滚动、遮挡、截断或无法证明完整，则结果为 `insufficient_evidence`，禁止低风险许可。图片等非文本内容只产生 `[图片]` 等占位符，不猜测语义。

### FR-06 保护策略

- 全局保护、按会话显示名称排除。
- 会话标签：`工作、客户、私人、家庭、其他`。
- 检测强度：`平衡、严格`。
- 用户高风险词和规则。
- 明确提示：显示名称不是稳定唯一标识，重名、改名和 OCR 错误可能导致规则失效。

### FR-07 风险分析

至少输出以下类别：

- `context_mismatch`：内容与当前场景不匹配；
- `hostile_tone`：攻击、辱骂或强烈抱怨；
- `sensitive_information`：隐私、凭据或敏感信息；
- `wrong_recipient_likelihood`：疑似选错对象；
- `user_rule_match`：命中用户规则；
- `insufficient_evidence`：证据不完整或不可信。

模型只输出建议；版本化策略引擎根据完整性、用户规则、分析信号和阈值生成最终动作。模型“安全”不得覆盖用户规则、证据不足或事务变化。

### FR-08 一次性许可

许可绑定 `窗口实例 + 会话指纹 + 草稿指纹 + 快捷键 + 策略版本`，仅消费一次，最长 10 秒失效；消费还要求后台 `VerifiedSnapshot` 不超过 300 ms。任意文本编辑、剪贴板变化、非预期前台切换、会话变化、锁屏、睡眠、配置变化或程序重启均使其失效。R0 许可、风险覆盖许可和 RX 跳过检测许可必须记录不同原因码；后两者在用户回到原目标后重新校验事务快照，但都只允许用户的下一次物理发送键通过。新鲜度过期时阻止该键、异步重检并要求再按一次，绝不补发。

### FR-09 弹窗与提示

- “正在检查”和“已检查”提示不激活、不抢焦点，且在截图完成后显示，避免进入采集图像。
- 风险窗口是独立受限窗口，默认取消，不设置自动发送倒计时。
- 文案使用“可能不适合当前聊天”“未能完成检测”等中性表达，不使用“违法”“违规”等无证据判断。
- 弹窗所在显示器与目标窗口一致，支持键盘操作、可见焦点和 200% 缩放。

### FR-10 日志与隐私

默认仅记录时间、结果、原因码、耗时、组件版本、模型哈希、置信度与错误码；不记录草稿、他人上下文、会话名称和截图。v1 主产品不提供“内容诊断”开关；需要复现时只能使用合成/已脱敏 Fixture 或用户在 `dc_uitag` 受控模式中另行管理的数据。元数据默认保留 14 天，可一键清除。

### FR-11 云端增强

- 默认关闭，首次启用展示供应商、字段、用途和保留政策。
- 允许字段仅为用户草稿、会话显示名称或本地别名、数值化语域分数；不得包含他人消息原文、截图、历史记录、联系人列表和账号标识。
- “会话显示名称”可能包含个人信息：默认只发场景标签或用户自定义别名；只有用户在启用页单独同意后才允许发送原显示名称。
- API 密钥存入 Windows Credential Manager，前端和 Python Worker 不接触明文。
- 供应商超时、限流、非法响应或熔断时回退本地结果；不得串行尝试多个供应商放大延迟和泄露面。

### FR-12 生命周期

支持托盘暂停/恢复、暂停 10 分钟、退出。退出、崩溃、锁屏、睡眠、目标进程退出时取消事务与许可，绝不补发。唤醒、显示器/DPI 变化、应用更新后重新验证兼容性。

## 8. 决策模型

| 等级 | 含义 | 产品动作 |
|---|---|---|
| R0 | 内容与场景匹配，证据充分 | 显示“已检查”，签发一次性许可 |
| R1 | 轻微语气或场景疑点 | 风险确认，默认返回修改 |
| R2 | 明显错配、攻击性或敏感信息 | 强提醒，默认返回修改 |
| R3 | 高度疑似严重误发或用户硬规则 | 二次明确操作后才签发许可 |
| RX | 文本/对象不完整、模型失败、超时或事务变化 | 显示未完成检测；取消、重新检测，或明确选择本次跳过后签发受限许可 |

优先级：用户规则 > 数据完整性 > 确定性本地规则 > 本地模型 > 云端建议。`decision_confidence` 与 `risk_score` 分开；置信度表达证据可靠程度，不等于风险严重度。

## 9. 异常与边界条件

必须覆盖：

- Enter 用于换行、Ctrl+Enter 用于发送及反向配置；Numpad Enter；左右 Ctrl。
- 中文拼音/五笔候选框、英文键盘、emoji 选择、输入法组合态。
- 长按、自动重复、快速双击；分析期间再次按键。
- 捕获、OCR、分析、确认任一阶段切换窗口、联系人、账号或继续编辑。
- 多窗口、多开账号、重名会话、窗口被遮挡或最小化。
- 空草稿、超长滚动草稿、大量 emoji、中英文混排、低对比主题。
- 100%–200% DPI、多显示器、负坐标、不同缩放、旋转屏、HDR。
- OCR 空结果、模型非法结构、Worker 崩溃、IPC 半帧、GPU 设备丢失。
- 网络断开、DNS/证书错误、限流、余额不足、超时。
- 锁屏、睡眠、远程桌面、安全桌面、权限完整性不同。
- 鼠标点击发送绕过保护；产品必须持续明确提示 v1 只保护配置的键盘发送方式。

## 10. 非功能指标

最低参考设备：4 核 CPU、8 GB 内存、集成显卡、1080p。

### 10.1 性能与资源

- 非目标键盘回调：p99 ≤ 0.25 ms，单次最大 ≤ 2 ms。
- 首次可见反馈：p95 ≤ 100 ms。
- 窗口捕获与裁剪：p95 ≤ 80 ms。
- 本地暖态完整分析：p50 ≤ 350 ms，p95 ≤ 800 ms，p99 ≤ 1.5 s。
- 云端增强硬超时：1.5 s；完整事务绝不超过 3 s 后无反馈。
- 非目标前台：平均 CPU ≤ 0.2%，GPU 0%，无固定频率截图或 OCR。
- 目标前台空闲：平均 CPU ≤ 1%，GPU 接近 0%。
- 隐藏待机总内存目标 ≤ 180 MB；模型活跃 ≤ 800 MB；显存 ≤ 512 MB。

### 10.2 正确性

- 支持矩阵内关键 ROI 定位成功率 ≥ 99.5%。
- 会话标题精确匹配率 ≥ 99%；可见中英文草稿 CER ≤ 2%。
- 文本完整性判断准确率 ≥ 99.5%。
- 高风险独立测试集召回率 ≥ 95%；正常消息误提醒率 ≤ 5%，目标 ≤ 3%。
- 10,000 次受保护发送：软件自动发送 0、重复发送 0、跨窗口许可消费 0。
- 1,000,000 次非目标按键：丢键、重复键和误阻止均为 0。

### 10.3 稳定性与隐私

- 72 小时持续运行无持续资源增长、无孤儿 Worker、无 Hook 静默失活。
- 默认配置全程零网络。
- 默认磁盘、日志、崩溃报告中无截图、草稿、他人消息和密钥。
- 云端抓包逐字段满足白名单；TLS 证书错误必须失败关闭。
- 主程序退出后无活动 Hook、Worker 或敏感临时文件。

## 11. v1 上线闸门

1. **可行性**：可靠阻止/物理重试、IME 兼容、截图完整性、端到端延迟四项技术尖峰通过，才进入全面实现。
2. **合规**：法务核对最终行为；CI 红线扫描、Process Monitor/API Monitor 验证通过。
3. **算法**：按设备/采集会话分组的独立保留集达到 ROI、OCR、召回和误提醒指标。
4. **安全**：10,000 次 E2E 中无自动发送、重复发送或上下文变化后放行。
5. **兼容**：支持矩阵内 Windows、微信、主题、DPI、多屏和输入法组合通过。
6. **性能**：最低设备达到延迟、CPU、内存和 72 小时稳定性门槛。
7. **隐私**：数据流、云端字段、密钥、日志清理、卸载清理和默认零网络验证通过。
8. **交付**：签名安装包、签名更新、篡改拒绝、升级、卸载和恢复测试通过。
9. **试运行**：至少 20 名用户、14 天、10,000 次受保护发送；无严重键盘干扰，误提醒率 ≤ 5%。
10. **文案**：安装页和产品内明确协议风险、能力边界、“仅辅助判断”和“鼠标发送不受保护”。
