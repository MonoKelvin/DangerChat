# 危信 v1.0 技术架构与接口设计

> 文档编号：DC-V1-ARCH｜版本：1.0-draft｜日期：2026-09-12｜状态：待评审
>
> 本文给出主产品可直接实施的模块、进程、状态机、协议和算法设计。所有设计受《合规与风险说明》的红线约束。

## 1. 架构目标

- 键盘快路径稳定：非目标应用无感，Hook 回调不执行耗时工作。
- 发送安全优先：已阻止的按键在任何失败状态下都不由软件补发。
- 默认本地和最小数据：截图、OCR 文本与上下文只在一次事务内存活。
- 可替换而不过度插件化：Windows、OCR、模型、云端供应商通过内部接口隔离，不加载第三方代码。
- UI、系统权限与推理解耦：WebView 不直接获得任意 Shell、文件、网络或捕获能力。
- 可测试：状态机与策略是纯领域逻辑，Win32、Tauri、Python 均可替换为测试端口。

## 2. 总体架构

```text
┌────────────────────────────────────────────────────────────┐
│ React + TypeScript + shadcn/ui（展示层）                    │
│ 设置 / 状态 / 日志 / 首次告知 / 风险确认 / 托盘交互        │
└───────────────────────┬────────────────────────────────────┘
                        │ 有限的 typed invoke / event
┌───────────────────────▼────────────────────────────────────┐
│ Tauri 2 + Rust（可信控制面）                               │
│ 应用生命周期、配置、托盘、窗口、策略、日志、密钥、云端网关 │
│                                                            │
│  ┌──────────────── dangerchat-guard ────────────────────┐  │
│  │ Hook / 前台观察 / 显示器捕获 / 事务状态机 / 许可     │  │
│  └───────────────────────────────────────────────────────┘  │
└───────────────────────┬────────────────────────────────────┘
                        │ 私有父子进程管道，长度前缀消息
┌───────────────────────▼────────────────────────────────────┐
│ Python Worker（计算面）                                    │
│ 图像预处理 / 区域定位 / OCR / 本地文本模型                 │
└────────────────────────────────────────────────────────────┘
```

推荐把 `dangerchat-guard.exe` 做成独立原生守卫进程，而不是让 Tauri WebView 生命周期承载键盘保护。UI 崩溃或隐藏时，守卫仍能安全取消事务并报告保护不可用。若技术尖峰证明单进程足够稳定，MVP 可先嵌入 Tauri Rust 主进程，但接口与线程边界保持不变。

## 3. 技术选型

| 层 | 推荐 | 原因 |
|---|---|---|
| 桌面壳 | Tauri 2 + Rust | Windows 系统 API、低资源、签名打包、能力权限 |
| 前端 | React + TypeScript + Vite | 类型契约、成熟生态、适合设置型桌面 UI |
| UI | shadcn/ui + Tailwind CSS v4 | 开放源码组件、语义变量、Radix 可访问性，减少散乱 CSS |
| 系统层 | Rust `windows` crate | v1 不引入 C++ DLL，减少 ABI、签名和崩溃边界 |
| Worker | Python 3.12+，PyInstaller onedir | OCR/ONNX 生态；用户无需安装 Python |
| OCR | 通过基准选择 RapidOCR/自建 ONNX PP-OCR 管线 | 中文小字号、可控部署、CPU/DirectML Provider |
| 本地推理 | ONNX Runtime | CPU、DirectML 可替换；固定线程和资源预算 |
| 元数据 | SQLite | 事务、迁移、筛选；不存聊天正文 |
| 配置 | 版本化 JSON + 原子写 | 人可读、易迁移；敏感值单独存储 |
| 密钥 | Windows Credential Manager | API Key 不进配置、前端和日志 |
| IPC | 父子进程匿名管道 + MessagePack | 无监听端口、二进制帧、低开销、可限长 |
| 日志 | Rust `tracing` + Worker 结构化 stderr | 跨进程同一事务时间线 |

不推荐在本机启动 FastAPI/localhost 服务：它引入端口发现、鉴权、防跨进程访问和防火墙问题，而 Worker 只需单父进程、单并发请求。只有未来需要多个受信任客户端时才重新评估。

## 5. 模块职责

### 5.1 `input_guard`（替代“消息源模块”）

负责系统发送意图的资格判断、按键阻止和一次性许可消费。不记录普通按键内容，不知道 OCR 或模型实现。

```text
InputGuard
  arm(TargetSnapshot)
  disarm(reason)
  set_health(Health)
  issue_permit(Permit)
  on_keyboard_event(event) -> Pass | Suppress | ConsumePermit
```

### 5.2 `target_observer`

通过系统窗口事件维护当前前台目标快照，使用 `SetWinEventHook(WINEVENT_OUTOFCONTEXT)`、`GetForegroundWindow`、根拥有者 HWND、PID、进程启动时间、DPI、显示器和边界。只查询操作系统已持有的当前窗口元数据，不枚举、扫描或读取目标进程内容。为遵守“不读取目标程序文件”，兼容选择不读取 EXE 文件版本，而使用 `layout_signature`：由当前屏幕的主题、物理尺寸、DPI 档位、稳定结构锚点及其几何关系形成版本化签名；签名必须排除 OCR 文本和聊天内容。未知签名一律进入“未经验证/需要重新校准”。

### 5.3 `screen_capture`

依合规边界捕获目标所在显示器，然后按 DWM 窗口边界裁剪。建议顺序：

1. DXGI Desktop Duplication：生产首选，显示器级 GPU 表面，先裁剪后读回。
2. Windows Graphics Capture 的“显示器捕获”：兼容路径；用户首次明确授权。
3. GDI `BitBlt`：最后兼容路径，仅可见屏幕区域。

不使用 UIA、`PrintWindow` 或向目标窗口请求渲染。Windows Graphics Capture 官方 API支持窗口或显示器帧、D3D11 frame pool、设备丢失重建；但窗口定向捕获是否符合本项目既定红线，由《合规与风险说明》裁决，当前实现只允许显示器目标。

### 5.4 `region_detector`

根据 `LayoutProfile` 输出 `chat_title、message_context、compose_input` 等区域及置信度。优先结构几何和布局配置，目标检测器只是可选适配器。

### 5.5 `ocr_engine`

接收裁剪区域，输出行、边界框、文本、字段置信度、模型版本与耗时。业务层不依赖具体 OCR 库。

### 5.6 `risk_analyzer`

分层执行本地归一化/规则、本地模型和可选云端模型，输出可解释的信号；不直接决定是否放行。

### 5.7 `decision_policy`

纯领域模块。结合证据完整性、用户策略、风险信号、截止时间和校准阈值，输出 `ALLOW_PERMIT | CONFIRM | UNAVAILABLE`。

### 5.8 `settings_registry`

每个模块注册 `key、type、default、validation、sensitivity、requires_restart、UI group`；启动时检测重复键和无效默认值。前端只读 Schema 并提交 Patch。

### 5.9 `diagnostics`

统一事件和健康状态。主产品不提供真实草稿、他人上下文或调试截图落盘；诊断只能使用结构化元数据、合成 Fixture 或不可逆的非内容特征。

## 6. 进程与线程模型

### 6.1 守卫进程

- `HookThread`：安装系统级 `WH_KEYBOARD_LL` 低级键盘钩子，独占消息循环；该钩子不注入目标进程。
- `WindowContextThread`：前台、窗口销毁、会话锁定、睡眠、显示器/DPI 事件。
- `CoordinatorThread`：状态机、截止时间、取消、许可和结果关联。
- `CaptureThread`：独占 D3D11/DXGI 资源，按请求抓取单帧。
- `IpcThread`：与 Tauri 和 Worker 通信。

Microsoft 文档明确指出低级键盘 Hook 在安装线程上下文中通过消息投递调用，线程必须有消息循环；回调超时后可能被系统静默移除，Windows 10 1709+ 最大超时按 1000 ms 处理。因此回调必须只做常量时间判断和有界队列写入，立即返回。

### 6.2 Python Worker

- 由可信 Rust 进程固定路径启动，加入 Windows Job Object，父进程退出即终止。
- 低优先级、默认 1–2 个推理线程、队列上限 1。
- 只接收内存图像和任务元数据；不枚举窗口、不捕获屏幕、不持有密钥、不对外联网。
- 目标离开前台 5 分钟后卸载推理 Session 和 GPU 资源；时间可配置。
- 1s、2s、5s 退避重启；10 分钟三次失败打开熔断器。

### 6.3 Tauri/React

只负责显示和用户输入。前端不得直接启动 Sidecar、读任意路径或发任意 HTTP；系统能力均通过白名单 Command 进入 Rust。主窗口与风险窗口使用不同 Capability，风险窗口只允许读取当前展示模型和提交决定。

## 7. 键盘 Hook 快路径

### 7.1 回调约束

`LowLevelKeyboardProc`：

- `nCode < 0` 立即 `CallNextHookEx`。
- 未启用、非目标、非精确快捷键立即透传。
- 不分配、不加锁、不格式化日志、不发 IPC、不截图、不调用 Python。
- 读取原子 `GuardSnapshot`，使用预分配 SPSC 队列和 CAS 创建事务。
- 内部目标 p99 ≤ 0.25 ms，最大 ≤ 2 ms，远低于系统超时。

### 7.2 按键配对

- Enter、Numpad Enter、Ctrl+Enter 分开配置。
- Shift/Alt/Win 或额外修饰键存在时，未显式配置则透传。
- 首次 keydown 创建事务后，阻止自动重复和配对 keyup。
- 在 `HELD/CAPTURING/ANALYZING/REVALIDATING/AWAITING_REVIEW/UNAVAILABLE` 等所有非空闲状态，新一轮已配置发送键的 keydown、repeat 和配对 keyup 也全部阻止，维持原事务且不排队；按 `vkCode + scanCode + extended` 的物理键身份维护配对。
- 即使期间前台变化，也必须阻止与已拦截 keydown 对应的 keyup，避免孤立事件。
- 分析期间普通编辑事件只递增 `user_activity_generation`，不记录具体键值；结果自动失效。

### 7.3 输入法

IME 组合态是 v1 最大兼容风险。通过输入法相关 WinEvent/TSF 可用状态和行为测试判断；无法确定 Enter 是候选确认还是发送时必须透传，不得误拦。首次配置优先推荐用户将 `Ctrl+Enter` 设为发送，以降低歧义，但不能替用户修改目标应用设置。

## 8. 状态机

```text
DISARMED
  └─目标有效且服务健康→ ARMED_IDLE
ARMED_IDLE
  ├─有效发送键→ HELD
  └─一次性许可匹配→ CONSUMED → 物理按键透传 → ARMED_IDLE
HELD
  └─按键配对处理完→ CAPTURING
CAPTURING
  ├─失败/超时→ UNAVAILABLE
  └─成功→ ANALYZING
ANALYZING
  ├─上下文变化→ CANCELLED_DIRTY
  ├─低风险→ REVALIDATING
  ├─风险→ AWAITING_REVIEW
  └─错误/超时→ UNAVAILABLE
REVALIDATING
  ├─快照不一致→ CANCELLED_DIRTY
  └─一致→ PERMIT_READY
PERMIT_READY
  ├─用户再次物理发送且许可匹配→ 原子消费，按键透传 → ARMED_IDLE
  └─许可失效/快照不一致→ CANCELLED_DIRTY → 重新检查
AWAITING_REVIEW
  ├─返回修改→ CANCELLED → ARMED_IDLE
  └─仍要发送→ REVALIDATING_OVERRIDE
REVALIDATING_OVERRIDE
  ├─快照不一致→ CANCELLED_DIRTY
  └─一致→ PERMIT_READY
UNAVAILABLE
  ├─取消→ CANCELLED → ARMED_IDLE
  └─选择“本次跳过检测”→ REVALIDATING_OVERRIDE
CANCELLED / CANCELLED_DIRTY
  └─清理事务和许可→ 根据目标健康状态进入 ARMED_IDLE 或 DISARMED
```

不允许任何异步结果跨事务生效。结果必须匹配 `transaction_id、context_generation、scene_fingerprint、draft_fingerprint、user_activity_generation`。

## 9. 一次性许可设计

```text
Permit {
  permit_id
  target_instance { root_hwnd, pid, process_start_time }
  context_generation
  scene_fingerprint
  draft_fingerprint
  shortcut
  policy_version
  issued_at_monotonic
  expires_at_monotonic
  consumed: AtomicBool
}
```

`AWAITING_REVIEW` 中点击“仍要发送”只记录 `override_approved`，不立即签 Permit。风险窗关闭后，只有原目标窗口重新成为前台才触发 CaptureThread 获取新快照并进入 `REVALIDATING_OVERRIDE`；若会话/草稿指纹一致，后台发布原子 `VerifiedSnapshot` 并签发 Permit。切换到任何非原目标窗口、编辑、剪贴板或配置变化都会撤销批准。

`VerifiedSnapshot` 包含 `context_generation、scene_fingerprint、draft_fingerprint、captured_at_monotonic、valid_until_monotonic`，默认新鲜度上限 300 ms；它由目标窗口前台事件和脏代次事件触发更新，不固定频率持续截图。Hook 收到发送键时只能 O(1) 比较当前代次、新鲜度、快捷键和 Permit 并原子消费。若快照超过 300 ms 或任一代次变化，Hook 阻止该次按键、撤销 Permit、发起一次异步复核；复核通过后提示用户再按一次物理发送键。严禁异步复核成功后补发刚才已阻止的事件。

许可不能持久化，进程重启即丢失。Permit 本身最长 10 秒，但每次消费仍要求上述 300 ms 新鲜快照；锁屏、睡眠、会话/窗口/草稿/配置变化立即撤销。

## 10. 截图与布局定位

### 10.1 捕获流程

1. 事务创建时冻结 `TargetSnapshot`。
2. CaptureThread 获取目标显示器最新帧。
3. 使用 Per-Monitor V2 DPI 感知下的物理坐标，将 DWM 扩展窗口边界与显示器交集裁剪。
4. 跨屏窗口分别裁剪并拼接；不同 DPI、旋转和 HDR 纳入显式转换。
5. 完整显示器表面只留在 GPU，先裁目标区域再读回 CPU。
6. 输出帧含 `frame_id、QPC 时间、目标快照代次、像素尺寸、色彩模式`。
7. 原始帧在任务结束释放，默认不落盘。

DXGI 可能返回 `DXGI_ERROR_ACCESS_LOST`；桌面切换、分辨率和旋转变化后必须重建。捕获到黑帧、窗口最小化或被其他窗口遮挡而内容不完整时返回失败，不猜测。

### 10.2 `LayoutProfile`

```json
{
  "schema_version": "1.0",
  "profile_id": "wechat-win-light",
  "profile_version": "1.2.0",
  "target_app": "wechat-windows",
  "layout_signatures": ["sha256:profile-geometry-signature"],
  "supported": {
    "themes": ["light"],
    "dpi_scale": [1.0, 1.25, 1.5, 2.0],
    "min_client_size": [800, 600]
  },
  "anchors": [
    {
      "id": "compose_separator",
      "method": "edge_geometry",
      "search_region": [0.25, 0.5, 0.75, 0.45],
      "min_confidence": 0.92
    }
  ],
  "regions": [
    {"role": "chat_title", "relative_to": "client", "bbox": [0.28, 0.0, 0.62, 0.11]},
    {"role": "message_context", "relative_to": "client", "bbox": [0.28, 0.11, 0.72, 0.57]},
    {"role": "compose_input", "relative_to": "compose_separator", "bbox": [0.0, 0.02, 1.0, 0.78]}
  ]
}
```

运行顺序：计算不含内容的 `layout_signature` 并选择唯一 Profile → 验证支持条件 → 多尺度结构锚点 → 修正归一化 ROI → 计算区域与整体置信度 → 低于阈值或签名未知进入 RX。若多个 Profile 同时匹配也视为不确定，不按“最接近”自动选择。优先使用分隔线、边缘和几何关系；不要把语言相关文字按钮作为唯一锚点。

### 10.3 YOLO 引入条件

只有配置定位在完整支持矩阵中无法达到关键 ROI ≥ 99.5%，且已有数百张以上独立场景、按设备/采集会话分组的数据时，才评估 `ObjectDetector`。10–20 张图只能做一个布局 Profile 的校准/概念验证，不能作为发布模型质量依据。

## 11. OCR 设计

```text
OcrEngine
  warm_up()
  capabilities() -> languages, providers
  recognize(image, regions, options, deadline) -> OcrDocument
```

```json
{
  "frame_id": "01J...",
  "region_role": "compose_input",
  "text": "最终要发送的文本",
  "confidence": 0.974,
  "complete": true,
  "lines": [
    {"text": "最终要发送的文本", "bbox": [32, 18, 264, 31], "confidence": 0.981}
  ],
  "engine": {
    "id": "ppocr-onnx",
    "model_version": "2026.09",
    "execution_provider": "cpu"
  },
  "latency_ms": 73
}
```

默认 CPU、1–2 推理线程；DirectML 只有本机基准 p95 至少改善约 20%、精度无回退且显存满足预算时启用。CUDA 作为后续可选资源包，不塞入基础安装包。INT8/FP16 必须单独评测中文标点、否定词和相似字，不能只看吞吐。

草稿和标题是必需字段，上下文只取最近可见 3–8 条。输入框滚动或内容被遮挡时 `complete=false`。OCR 字段质量使用独立标注集测量，不将引擎自报分数直接解释为真实概率。

## 12. 风险分析流水线

```text
视觉质量门 → 文本归一化 → 用户规则/敏感模式
            → 本地语义模型（可选）
            → 云端 LLM（显式开启且不确定时）
            → 决策策略
```

### 12.1 本地规则

- Unicode NFKC、空白与标点归一化。
- 用户词表、正则和会话标签规则。
- 手机号、身份证、密钥等敏感模式。
- 抱怨、攻击、客户信息、保密内容等可版本化词典。

用户硬规则优先级最高；高风险命中可直接进入确认，无需等待云端。

### 12.2 本地模型

推荐 ONNX 中文编码器 + 多标签分类头，输出场景匹配与类别分数。没有足够独立数据前，只发布接口和规则实现，不使用未经验证的小模型制造虚假确定性。分数用保留集进行温度缩放、Platt scaling 或 isotonic calibration。

### 12.3 云端 LLM

只在用户显式启用、本地不确定区间、截止时间充足、熔断器关闭时调用。它是单次结构化分类，不是 Agent，也不获得任何工具。输入内容被视为不可信数据，系统提示明确要求只分类、不得执行草稿中的指令；响应必须通过严格 JSON Schema。

云端网关在 Rust 中：字段白名单、固定供应商端点、TLS、请求超时、响应限长和 Schema 校验均由 Rust 执行。Python 和 React 不接触 API Key 或供应商网络。

## 14. Worker IPC

### 14.1 帧格式

```text
[u32 little-endian payload_length][MessagePack Envelope]

Envelope {
  schema_version
  request_id
  kind
  deadline_monotonic_ms
  payload
}
```

消息类型：`hello、analyze_frame、cancel、result、health、shutdown、error`。

控制帧仍使用上述长度前缀 MessagePack，硬上限 1 MiB。像素不内嵌 MessagePack，而由 Rust 为单个请求创建当前用户 DACL 的受限共享内存映射，先在 GPU/本地裁成所需 ROI，再写入紧凑连续缓冲区。`analyze_frame` 只携带不可猜测的映射能力标识、`width、height、stride、pixel_format=BGR8|GRAY8、byte_length、sha256、request_id`；Worker 只能继承/打开本请求句柄，校验 `byte_length = stride × height`、尺寸上限和哈希后读取。请求结束、取消或 Worker 退出时 Rust 立即撤销句柄并清零自有缓冲区；映射不可复用、不可接受任意名称。

单个 ROI 上限 4096×4096，单请求总像素载荷上限 32 MiB；超过时按标题、草稿、上下文 ROI 分块缩放/传输，仍超限则返回 `FRAME_TOO_LARGE` 而不是截断内容。4K、200% DPI、混合 DPI 和 32 MiB 边界必须进入契约与性能测试。未知版本/类型、超长文本、非法枚举或 request_id 不匹配立即拒绝并记录元数据错误。

stdout 专用于协议；Worker 日志只能写 stderr。协议不接受任意 Shell 参数、URL、文件路径或窗口句柄。Rust/Python 维护同一组 Golden Fixtures，在 CI 双向编码/解码。

### 14.2 握手

Worker 返回协议版本、Worker 版本、模型清单哈希、Provider、线程配置和能力。Sidecar/模型文件 SHA-256 与只读 Manifest 不匹配时拒绝分析，但 UI 必须仍可启动并显示修复指引。

## 15. 配置与数据

通过 Tauri Path Resolver 获取：

| 内容 | 目录 |
|---|---|
| Sidecar、默认配置、内置模型 | `resource_dir` |
| 用户设置 | `app_config_dir/settings.json` |
| SQLite 元数据 | `app_local_data_dir/app.db` |
| 模型缓存/更新临时文件 | `app_cache_dir` |
| 运行日志 | `app_log_dir` |

设置写入临时文件、flush 后原子替换，并保留一个已知有效备份；未知字段拒绝。SQLite 只存设置迁移、组件状态和拦截元数据，不设计消息正文列。敏感内容用类型系统区分，禁止实现 `Display/Debug/Serialize` 到普通日志。

## 16. 日志与可观测性

统一 JSONL：

```text
timestamp, level, component, event, session_id,
transaction_id, stage, duration_ms, result_code,
app_version, profile_version, model_hash
```

建议单文件 10 MiB、最多 5 个、保留 14 天。主产品日志只包含结构化元数据，禁止提供保存草稿、会话原文、上下文或截图的调试开关。诊断包由用户主动导出，自动移除用户名、绝对路径和密钥；算法复现使用合成/已脱敏 Fixture，不从生产会话落盘取材。

关键指标：Hook 时延、各阶段 p50/p95/p99、取消原因、布局/OCR 失败率、Worker 重启、熔断状态、内存/显存峰值。默认不上传遥测。

## 17. 安全边界

- Tauri CSP 只允许打包资源和自身 IPC，不加载远程脚本/页面。
- 前端 Capability 不授予通用 `shell:*`、`fs:*`、任意 HTTP；Sidecar 只可由 Rust 以固定名称启动，不能开放 `args: true` 给 WebView。
- 主窗口和风险窗口最小权限分离；前端提交的 ID、枚举和文本长度均在 Rust 重验。
- Worker 父子管道无监听端口；若拆成独立守卫命名管道，DACL 仅当前用户 SID并校验客户端进程身份。
- API Key 只在 Rust Cloud Gateway 从 Credential Manager 短暂读取。
- OCR/模型/云端输出全部视为不可信数据，不能形成命令、路径或 HTML。
- 所有发布 EXE/DLL/安装器做 Authenticode；模型和 Sidecar 校验 Manifest 哈希。

## 18. 失败与降级

1. 云端失败：使用本地结果，标记 `degraded`；不尝试第二供应商。
2. 本地模型失败：回退规则。
3. OCR/布局不可信：`UNAVAILABLE`，不得签发低风险许可。
4. Worker 崩溃/IPC 断开：当前事务不发送，退避重启。
5. Capture Device Lost：当前事务失败，后台重建。
6. Hook/协调器不健康：阻止当前一次发送并明确提示，然后转为“不受保护”，不能静默假装正常。
7. UI 崩溃：守卫取消待确认事务，原生通知保护不可用。
8. 退出/锁屏/睡眠：撤销全部许可与事务，清除帧，绝不补发。

## 19. UI 信息架构与设计规范

### 19.1 设计方向

产品意象是“安静的发送闸”，不是 AI 仪表盘。唯一视觉记忆点是窗口右侧 3 px 的“状态轨”：守卫蓝表示保护中，琥珀表示分析/提醒，灰色表示暂停或不可用。其余界面保持克制，避免渐变、玻璃拟态、大阴影、巨型 KPI 和装饰性图表。

色彩：背景 `#F6F8FA`、面板 `#FFFFFF`、主文字 `#202832`、次文字 `#667381`、守卫蓝 `#376B8C`、警告琥珀 `#B36A2E`、高风险红 `#B94742`、边界 `#DEE4E9`。使用语义 CSS Variables，不在组件中散落色值。

字体：标题 `Segoe UI Variable Display, Microsoft YaHei UI`；正文 `Segoe UI, Microsoft YaHei UI`；延迟、版本、模型 ID 使用 `Cascadia Mono, Consolas`。8 px 间距网格、10–12 px 圆角、1 px 冷灰边界。

### 19.2 主窗口

```text
┌ 自定义标题栏 ─────────── 状态 / 最小化 / 关闭 ┐
│ 状态       │ 当前页面标题                        │
│ 保护范围   │ ───────────────────────────────    │
│ 检测       │ 设置组                              │
│ 提醒       │                                     │
│ 隐私       │                            状态轨   │
│ 日志       │                                     │
│ 关于       │                                     │
└────────────┴─────────────────────────────────────┘
```

820×600，最小 720×520；左侧 184 px，右侧 `ScrollArea`。设置组用标题、短说明和右对齐控件，不把每项包成卡片。自定义无边框标题栏使用 Tauri drag region，窗口保持不透明并交由 DWM 处理阴影。关闭默认隐藏托盘，首次仅提示一次。

### 19.3 组件与可访问性

使用 shadcn/ui `Sidebar、ScrollArea、Switch、Select、Slider、Button、AlertDialog、Table、Tooltip`。shadcn 当前 Vite 模板以 Tailwind CSS 和语义 CSS Variables 为基础；Dialog 的 Radix 原语提供焦点圈定、滚动锁和 Escape 行为，不另写脆弱的焦点陷阱。

所有控件支持键盘、可见焦点、4.5:1 对比度、屏幕阅读标签和 200% 缩放；尊重 `prefers-reduced-motion`。动画只用 120–160 ms 的透明度/轻微位移。

### 19.4 状态提示

“正在检查”“已检查，再按一次发送”使用不抢焦点的小浮层，2–3 秒后消失；截图完成后才显示。安全提示不是模态框。

### 19.5 风险确认窗口

独立 Tauri 窗口，约 420×300，置顶、固定大小：

```text
这句话可能不适合当前会话
收件场景：项目工作群

• 包含明显抱怨语气
• 与当前工作场景不一致

[返回修改]              [仍要发送]
```

默认焦点和主按钮为“返回修改”；`Esc` 返回；Enter 不触发“仍要发送”。理由最多三条，不展示概率小数、模型名称或推理过程。“仍要发送”只记录 `override_approved`；用户回到原聊天窗口后完成新鲜快照复核，复核成功才提示“再按一次发送”。

## 20. 外部依赖事实核对

截至本文日期，Tauri 2 官方文档支持通过 `bundle.externalBin` 打包 Sidecar，并可由 Rust 端 spawn 后读写 stdin/stdout；Capability 可限定 Shell 执行范围。官方 Windows 安装文档提供 WebView2 download/bootstrapper/offline/fixed runtime 模式，离线安装器约增加 127 MB；Updater 产物具有独立签名文件。以上只是框架能力，危信仍采用比通用示例更小的权限：WebView 不直接获得可变参数 Sidecar 执行权。
