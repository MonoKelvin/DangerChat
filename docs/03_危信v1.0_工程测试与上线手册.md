# 危信 v1.0 工程、测试与上线手册

> 文档编号：DC-V1-DELIVERY｜版本：1.0-draft｜日期：2026-09-12｜状态：待评审
>
> 本文定义从仓库初始化、开发、验证到签名发布和运维的可执行流程。

## 1. 开发原则

1. 每个行为有可测验收条件，先证明核心可行性再全面重构。
2. 合规红线进入代码、依赖、CI、PR 模板和发布验证，不只写在文档中。
3. 所有依赖、工具链、模型和 Action 固定版本或提交 SHA；更新走显式 PR。
4. 默认零网络、无内容日志、普通权限运行。
5. 不为假想扩展实现公共插件系统；内部端口只覆盖真实可替换边界。
6. 一次变更只解决明确需求，不顺手增加自动化或目标程序能力。

## 2. 开发环境与版本锁定

建议在首个实现 PR 中生成并提交：

- `rust-toolchain.toml`：固定 stable 小版本与 `rustfmt/clippy`。
- `package.json` + `pnpm-lock.yaml`：Node LTS、pnpm 固定版本。
- `pyproject.toml` + `uv.lock`：Python 3.12，小版本与哈希锁定。
- `models/manifest.json`：模型 ID、版本、SHA-256、许可证、预处理和阈值版本。
- `.github/dependabot.yml` 或 Renovate 配置：只创建评审 PR，不自动合并。

Windows 开发机需要：Visual Studio Build Tools（MSVC/Windows SDK）、Rust、Node/pnpm、Python/uv、WebView2、EdgeDriver（E2E）、代码签名工具。生产构建只能在受控 Windows runner 上完成。

## 3. 技术尖峰 M0

重构前先用最小原型验证四项，原型不进入发布分支，除非通过评审重写为生产代码。

### 3.1 键盘阻止与物理重试

验证：

- `WH_KEYBOARD_LL` 专用线程和消息循环。
- 精确识别 Enter/Numpad/Ctrl+Enter，正确处理 repeat/down/up。
- 第一次阻止；完成分析/覆盖批准后，只有后台复核生成 ≤300 ms 的新鲜快照时，下一次物理发送键才可消费许可并透传。过期发送键必须被阻止，复核后要求再按一次，绝不异步补发。
- 目标切换、继续输入、超时后许可失效。
- 不调用任何输入注入 API。

通过门槛：目标外 100,000 次事件零误阻止；目标内 10,000 次事务零重复、零孤立 keyup；p99 回调 ≤ 0.25 ms。100,000 次仅为 M0 预门槛；Release 必须按第 17 章执行 1,000,000 次非目标按键正式门槛。

### 3.2 IME

覆盖微软拼音、五笔、英文键盘，测试候选框、组合文本、emoji 面板、Enter 换行及快捷键反向设置。无法可靠判断的组合必须透传。通过门槛：候选确认零误吞；真实发送意图识别满足支持矩阵。

### 3.3 截图、区域与 OCR

在 100/125/150/200% DPI、浅/深主题、至少三种窗口尺寸、多屏下，完成显示器捕获、窗口裁剪、标题/草稿 ROI 与 OCR。通过门槛：关键 ROI ≥ 99.5%，标题精确匹配 ≥ 99%，草稿 CER ≤ 2%，错误布局不得静默判为安全。

### 3.4 端到端延迟

暖态本地流程从物理按键到提示可见，最低参考设备 p95 ≤ 800 ms；100 ms 内出现处理中反馈。若达不到，先优化捕获、ROI 和 OCR，再讨论模型，不得通过取消完整性检查换速度。

M0 任一项不通过时，产品负责人必须调整范围或停止全面实现，不能以“后续优化”跳过。

## 4. 实施顺序

### M1 工程骨架

1. Workspace、Tauri/React、Rust crates、Python package。
2. typed Command/Event、Worker 协议 Golden Fixtures。
3. 配置注册表、SQLite 迁移、结构化日志。
4. 主窗口、托盘、风险窗口静态流程。
5. Sidecar 打包、握手、Job Object 与退出清理。

### M2 本地 MVP

1. Target Observer 与 Hook 快路径。
2. 发送事务、取消和一次性许可。
3. DXGI/WGC 显示器捕获与裁剪。
4. LayoutProfile、OCR、完整性门。
5. 本地规则、决策策略、风险提示。
6. 首次告知、保护状态自检、默认零网络。

### M3 算法和兼容

1. `dc_uitag` 数据生产线。
2. 独立训练/验证/测试集及基线。
3. 可选本地分类器和置信度校准。
4. 可选云端供应商适配器。
5. 支持矩阵、性能与长稳优化。

### M4–M5 交付

安装/签名/更新、隐私与安全测试、Beta 试运行、缺陷收敛、Stable 发布。

## 5. 编码规范与边界

### 5.1 Rust

- `unsafe` 仅允许在 `platform-windows` 的小范围 Win32 封装中，逐块解释不变量并配测试。
- Hook 回调不得 panic；FFI 边界捕获失败并转为安全状态。
- 领域状态机不依赖 Tauri、Win32、SQLite 或 Python。
- 截止时间统一使用单调时钟，持久时间才使用 UTC。
- 敏感缓冲区建立专用类型，退出作用域尽可能清零，但不宣称能清除所有运行时副本。

### 5.2 TypeScript/React

- `strict` 开启；不使用 `any` 穿透 IPC。
- 前端类型由契约生成或共享 Schema 派生，不手写重复枚举。
- Tauri invoke 集中于 service adapter，组件不直接拼命令名。
- 页面级 Error Boundary；日志页 lazy load；设置提交提供保存中、失败和已保存状态。
- 不使用 `dangerouslySetInnerHTML` 渲染模型/OCR 文本。

### 5.3 Python

- 所有协议模型强类型校验；未知字段拒绝。
- stdout 只能发协议帧，日志写 stderr。
- 推理会话线程数显式设置；禁止隐式下载模型或运行时联网。
- 模型、预处理、标签、阈值都由 Manifest 固定。
- 不接受任意路径、URL、模块名或表达式执行。

## 6. 配置与数据库迁移

每个持久化格式包含 `schema_version`。迁移是确定性的单向函数，并有旧版本 Fixture。写配置采用临时文件 + flush + 原子替换；失败恢复最后有效备份。SQLite 启动时事务迁移，失败进入只读诊断状态，不创建空库掩盖问题。

禁止在数据库中新增聊天正文、他人消息或截图列。若未来业务声称需要，必须先修改合规文档和完成安全评审。

## 7. 测试分层

### 7.1 单元测试

**Rust domain**：

- 状态迁移的所有合法/非法路径。
- 一次性许可绑定、批准后复核、300 ms 新鲜快照、过期后阻止并重检、原子消费和撤销。
- 所有非 idle 状态对新一轮发送 keydown/repeat/keyup 的阻止与物理键配对；覆盖快速双击和“松开后再按”。
- 快捷键精确组合、repeat/down/up 配对。
- 策略优先级、阈值边界、超时和降级。
- 配置验证/迁移、日志脱敏、裁剪坐标和 DPI 转换。

**Python**：

- 图像预处理、ROI、OCR 后处理、完整性判断。
- CPU/DirectML Provider 选择和失败回退。
- 规则分类、模型输出 Schema、截止时间和取消。
- 模型 Manifest 哈希、版本不匹配和损坏模型。

**React**：

- 首次告知未同意时不能启用。
- 设置保存成功/失败/冲突。
- 所有保护状态、空状态和错误状态。
- 风险窗口默认焦点、Esc、Enter 禁止危险确认。
- axe 可访问性和 200% 缩放关键布局。

### 7.2 契约测试

- Rust/Python 对每种 IPC 消息使用相同 Golden Fixture 双向编码。
- 前端/Rust 的 Command、Event、错误码生成类型并做快照测试。
- 云端适配器对供应商响应进行 Schema、超长、未知枚举、Markdown 包裹、提示注入文本测试。
- 配置和 LayoutProfile 的 JSON Schema 向后兼容测试。

### 7.3 进程集成测试

- Worker 启动超时、异常退出、半帧、坏长度、超大控制帧、共享内存句柄伪造/复用、stride/byte_length 不一致、32 MiB 边界和请求 ID 错误。
- 4K、200% DPI 和混合 DPI ROI 通过受限共享内存完成，不发生隐式截断；超限稳定返回 `FRAME_TOO_LARGE`。
- 主进程退出后 Job Object 无孤儿进程。
- 模型缺失/哈希错误时 UI 可启动，保护状态明确不可用。
- GPU Device Lost、CPU 回退、休眠恢复、熔断与退避。
- 命名/匿名管道访问控制和伪造客户端拒绝。

### 7.4 UI E2E

使用 Windows runner 上的 `tauri-driver`/WebDriverIO 覆盖：

- 首启告知与配置向导。
- 托盘打开、暂停 10 分钟、关闭隐藏、真正退出。
- 设置持久化、主题、日志筛选和清除。
- 正在检查、安全提示、风险确认、许可过期。
- 更新开关和更新错误状态。

UI E2E 不替代真实键盘/微信测试；后者由专用 Windows Harness 和人工矩阵执行。

### 7.5 系统与真实场景 E2E

构建一个自有测试聊天窗口 Harness，模拟标题、上下文、输入框和发送行为，用于自动跑 10,000 次事务；绝不依赖向微信注入测试输入。真实微信兼容由受控人工测试使用物理键盘完成。

每个阶段都注入窗口切换、草稿改变、Worker 崩溃和超时，断言消息未发送、许可未泄漏、状态可恢复。

## 8. 算法评估

### 8.1 数据切分

按设备、用户授权采集会话或屏幕配置 `group_id` 分组切分，不能随机拆分相邻截图。增强数据不替代真实主题、DPI、窗口和版本多样性。发布后的验证集/测试集冻结，训练过程不可见。

### 8.2 指标

- ROI：关键区域成功率、IoU、错误区域静默通过率（必须为 0）。
- OCR：CER、标题 exact match；否定词、数字、标点单列指标。
- 风险：每类 precision/recall/F1、宏平均、高风险 recall、正常误提醒率。
- 场景错配：按工作群、客户、私人、未知分片。
- 校准：ECE ≤ 0.05、Brier Score、可靠性图。
- 性能：每阶段及端到端 p50/p95/p99，冷/暖态分开。

阈值只能由验证集选择，测试集只在候选冻结后运行一次。报告同时给总体和主题、DPI、消息长度、语言混排等切片，不能只给平均值。

## 9. Windows 兼容矩阵

- Windows 10 22H2、Windows 11 当前受支持版本。
- 发布支持矩阵中的明确 `layout_signature`；不读取目标程序 EXE 版本资源。未知或多义签名默认提示重新校准，不能按最相近 Profile 自动放行。
- 100/125/150/200% DPI；单屏、双屏、负坐标、混合缩放、旋转、HDR。
- Intel/NVIDIA/AMD/纯 CPU。
- 微软拼音、五笔、英文键盘；其他输入法列为实验性或不支持。
- 浅色/深色、正常/最大化、最低支持窗口尺寸。
- 锁屏、睡眠、显示器热插拔、远程桌面、安全桌面。
- 普通权限；目标应用以更高完整性运行时明确标记不支持，不提升危信。

支持矩阵是一份发布制品，不能用“理论支持所有版本”替代实际测试。

## 10. 性能与稳定性测试

### 10.1 基准

使用固定设备档位和数据集，保存原始结果：

- Hook callback 直方图。
- Capture/裁剪、布局、各 OCR 区域、规则、本地模型、云端时间。
- CPU、私有工作集、GPU、显存、线程数、句柄数。
- 冷启动、Worker ready、模型预热、释放后重载。

PR 只运行小基准防明显回退；夜间跑全矩阵；Release 跑最低设备门槛。相对基线回退 >10% 或绝对门槛失败阻断发布。

### 10.2 长稳

72 小时：目标前台/后台切换、周期性事务、Worker 故障、睡眠唤醒。监控内存、句柄、线程、GPU 和磁盘日志；不允许单调增长。Hook 看门狗不得向目标程序注入测试事件；若存在合规文档所述自进程探针，必须被自身 Hook 消费并有唯一静态白名单。

## 11. 安全与隐私测试

- 静态红线扫描：`ReadProcessMemory、WriteProcessMemory、CreateRemoteThread、SendInput、keybd_event、mouse_event` 及外部窗口消息 API；唯一自探针按文件+函数白名单。这里的白名单仅对应《合规与风险说明》允许的自进程 Hook 存活探针，探针事件必须带随机自标记并由本进程 Hook 消费，运行前后校验前台不是目标窗口；若无法证明这些条件则禁用探针。业务 crate、目标窗口句柄和任何发送事务均不得引用该接口。
- 依赖扫描：禁止微信逆向/自动化依赖；`cargo deny`、npm/Python 漏洞和许可证检查。
- Tauri Capability：无通用 Shell/FS/HTTP；CSP 无远程脚本和导航。
- IPC Fuzz：长度、递归、超大字段、未知类型、乱序、截断。
- OCR/LLM 提示注入：输入只作为数据，不改变命令或配置。
- 云端抓包：安装测试根证书，在授权环境解 TLS，逐字段验证白名单；他人上下文和截图绝不出现。
- 默认零网络：DNS、TCP、HTTP 全程观测；更新和云端均关闭时连接数为 0。
- Process Monitor/API Monitor：不访问微信目录、内存、模块，不投递输入/窗口消息。
- 日志与崩溃：全文扫描草稿、联系人、截图特征和 API Key。
- 更新：篡改包、签名、清单、版本、重放和降级全部拒绝。
- `dc_uitag` ZIP：Zip Slip、重复类 ID、越界框、炸弹包与损坏图片。

## 12. CI 流水线

### 12.1 Pull Request

并行 Job：

1. Frontend：锁文件安装、ESLint、TypeScript、Vitest、Testing Library、axe。
2. Rust：`cargo fmt --check`、Clippy（warnings denied）、unit/integration、`cargo deny`。
3. Python：ruff、类型检查、pytest、依赖和许可证扫描。
4. Worker package smoke：`hello → analyze fixture → shutdown`。
5. Contract：Rust/Python Golden Fixtures、前后端 Schema。
6. Tauri：Windows debug build + UI E2E。
7. Compliance：红线 API/依赖扫描、默认网络权限检查。
8. Supply chain：SBOM、许可证清单、secret scan。

第三方 GitHub Actions 固定完整 commit SHA。Fork PR 无发布密钥、签名证书、云端 API Key 或更新私钥。

### 12.2 Nightly

- Windows/DPI/Provider 扩展矩阵。
- OCR/风险完整固定集。
- 性能回归、IPC Fuzz、安装/卸载冒烟。
- 长稳任务分片执行。

## 13. 打包

### 13.1 Python Worker

PyInstaller `--onedir`，不使用 `--onefile`：避免每次启动解压、便于哈希与诊断，也通常降低杀毒误报。Python 解释器、ONNX Runtime 和必需模型随包，用户无需安装 Python/CUDA。Sidecar 主 EXE 按 Tauri `externalBin` 目标三元组命名，DLL/模型作为只读 resources。

基础包只含 CPU Provider；DirectML 可随基础包或可选组件，以实际体积/兼容测试决定。CUDA 仅后续独立包。

### 13.2 Windows 安装器

主发行推荐 Tauri NSIS `currentUser`，运行时不提权。提供：

- 在线小包：缺少 WebView2 时使用官方 Evergreen Bootstrapper。
- 离线包：`webviewInstallMode: offlineInstaller`，体积约增加 127 MB；需在无网络、无 WebView2 的干净 VM 验证。

企业 MSI/per-machine 后续提供，不作为 v1 首发阻塞项。

## 14. 签名与供应链

两类签名分开管理：

1. **Authenticode**：Worker EXE/DLL、守卫、Tauri 主程序、卸载器和最终安装包，SHA-256 + 可信时间戳。
2. **Tauri Updater 签名**：独立更新私钥签更新制品，公钥嵌入应用。

更新私钥置于 HSM/受保护 CI secret，并离线备份；制定轮换过渡版本。签名证书和私钥不对 PR/Fork 暴露。构建生成 CycloneDX/SPDX SBOM、第三方许可证、模型许可证和 SHA-256 清单。

构建应尽量可复现：固定 runner 镜像、工具链、依赖和时间源；签名前比较未签名制品哈希，签名后重新冒烟。

## 15. 更新策略

因默认零网络，自动检查更新默认关闭。用户可开启每日最多一次检查或手动检查。

- 固定 HTTPS 域名，清单严格 Schema。
- 验证 Updater 签名、版本和平台；不允许降级。
- 分析、风险窗或许可有效期间不安装。
- 下载后由用户点击“重启并更新”。
- 先 beta 后 stable；更新清单分通道。
- 新版本首次启动迁移失败时回滚程序或进入只读恢复，不覆盖最后有效用户配置。

## 16. Release 流程

```text
tag vX.Y.Z
→ 校验所有组件/协议/模型版本一致
→ 干净 Windows runner 构建 Worker
→ 签 Worker 与依赖 DLL
→ Worker package smoke
→ 构建 Tauri + NSIS 在线/离线包
→ Authenticode 签主制品
→ 生成并签 Updater 制品
→ 生成 SHA-256、SBOM、licenses
→ 干净 VM 安装/启动/升级/卸载/零网络测试
→ 真实设备兼容与性能门槛
→ Draft Release
→ 产品/安全/法务人工批准
→ beta 分阶段发布
→ 观察后 stable
```

不得直接从开发机发布。Draft Release 在所有批准前不可公开；回滚通过停止清单投放和发布修复版本，不通过给客户端下发旧版本降级。

## 17. 发布阻断清单

以下任一失败不得发布：

- [ ] 默认配置全程零网络。
- [ ] 不访问微信目录、进程内存、模块、数据库或网络。
- [ ] 无向目标程序输入注入、窗口消息或自动发送。
- [ ] 默认日志、磁盘、崩溃包无截图、草稿、他人消息和密钥。
- [ ] 云端请求仅含已批准字段，并有用户显式同意。
- [ ] Tauri WebView 无任意 Shell、文件系统、HTTP 或远程导航权限。
- [ ] Sidecar/模型哈希不符时拒绝分析且 UI 可恢复。

## 18. Beta 与上线后运营

### 18.1 Beta

至少 20 名明确知情用户，14 天、10,000 次受保护发送。只收集用户主动提交的脱敏反馈；默认无遥测。关注：严重键盘干扰、误吞、无法恢复、误提醒率、平均额外操作、Worker/布局失败率。

严重级别：

- S0：软件造成非用户授权发送、重复发送或敏感数据外发——立即停止发布。
- S1：广泛丢键/卡键、保护状态虚假、更新不可恢复——暂停通道并热修复。
- S2：特定环境不兼容、明显性能回退——从支持矩阵移除或下版本修复。

### 18.2 兼容性响应

目标应用 UI 更新后，新计算的 `layout_signature` 默认进入“未经验证”，不自动沿用最相近旧 Profile 产生低风险许可；为遵守不读取目标程序文件的红线，v1 不通过 EXE 版本判断。维护者在隔离测试矩阵验证后签发新的 Profile/签名/模型清单。兼容数据更新与程序更新同样需要签名、版本和回滚。

### 18.3 定期工作

- 每季度复查微信协议与隐私条款。
- 每月依赖漏洞、许可证、签名证书和更新密钥健康检查。
- 每个 Release 重跑合规、隐私、性能和真实支持矩阵。
- 发布后保留构建日志、SBOM、哈希、签名验证和测试报告，但不保留用户内容。

## 19. Definition of Done

一个功能只有在以下全部成立时完成：需求 ID 与边界明确；代码和迁移完成；单元/契约/集成测试通过；关键 UI 在真实应用运行验证；性能和隐私无回退；错误与空状态可操作；文案和可访问性通过；未触碰红线；必要的运维/诊断路径存在。仅“编译通过”或“模型样例成功”不构成完成。
