## M0-C 捕获、区域定位与 OCR

### 已通过：捕获与裁剪

`m0 capture-probe 30`，单屏 1920×1080、DPI 96：

| 指标 | 实测 | 门槛 | 结果 |
|---|---|---|---|
| 捕获裁剪 p50 | 32.7 ms | — | — |
| 捕获裁剪 p95 | 37.1 ms | ≤ 80 ms | PASS |

当前走的是降级链最后一级 GDI。DXGI Desktop Duplication 与 WGC 显示器捕获**尚未接入**，
预期更快，但未实测。

### 已通过：区域定位

`m0 layout-eval`，自有合成测试窗口，8 个场景（4 种窗口尺寸 × 浅/深主题）：

| 指标 | 实测 | 结果 |
|---|---|---|
| 关键 ROI 达标场景 | 8 / 8 | PASS |
| 最低 IoU（聊天标题） | 0.982 | PASS |
| 最低 IoU（消息上下文） | 0.996 | PASS |
| 最低 IoU（输入框） | 0.991 | PASS |
| 定位耗时平均 | 3.0 ms | — |

定位只使用灰度、边缘梯度与行列一致性，不依赖文字内容，也不使用目标检测模型。
结构签名由几何比例构成，不含任何文本。

**实现过程中发现并修正的问题**：最初按 DWM 扩展边界裁剪，导致窗口自身的标题栏
被当作界面结构，深色主题下标题区 IoU 为 0。改为按客户区
（`GetClientRect` + `ClientToScreen`，同属操作系统窗口管理接口）裁剪后解决。
